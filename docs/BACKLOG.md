# Pulsix backlog

Planning backlog for Pulsix, the NoiXdev server management and monitoring platform.
One line per deliverable, grouped by milestone. Update the status column as work moves.

Status legend: `idea` · `mockup` · `spec` · `planned` · `in progress` · `done`

The status column is only useful if it is true. `done` means the thing
ships and is covered by tests — not that a plan once named it. When part
of a row ships and part does not, the row says which part (see 1.1b,
1.12, 1.19): half-truths here cost more than an open row, because the
next person reads this table instead of the code.

**v0.3b-3 shipped (2026-10-01)** — *discovery and item decisions*, the last of
three cuts of v0.3b (spec
`docs/superpowers/specs/2026-10-01-v0.3b-3-discovery-design.md`, plan
`docs/superpowers/plans/2026-10-01-v0.3b-3-discovery.md`). What a check
measures is now a thing the product knows about, not a string an operator
retypes from memory: `internal/items` (migration 00048) records every
(host, check_key, item) the evaluation ticker's own `Load` sees, and an
operator can decide one item — or a `*` pattern of them — should stop being
judged, at the organization or at one host, with a host decision always
outranking an organization one. Ignoring never stops measurement, only the
verdict: `internal/rules`' own `Apply` deletes the stored state of a
newly-ignored tuple so a `crit` does not sit unrefreshed, and a decision's
own write marks the affected host(s) due again so it takes effect on the
next tick rather than at their own staleness deadline. The Items tab
(`web/src/features/checks/ItemsPage.tsx`) lists every decision with a
pattern editor that previews its match count before anything is saved; the
host page's monitoring card offers a one-click ignore/watch per row and
says where an ignore came from. `internal/e2e/items_test.go` and
`web/e2e/items.spec.ts` prove the whole arc on a real agent: a mount
crossing a threshold reaches `crit`, ignoring it returns the host to `ok`
with the tuple itself carrying no state, watching it again returns the host
to `crit`. Closes 3.6c — which, as its own corrected note says, was already
half done before this milestone started. **v0.3b itself is now complete:**
measurement (v0.3b-1), judgement (v0.3b-2) and discovery (v0.3b-3).

## Decisions (short)

- Stack: Go (manager, worker, agent), React/TypeScript SPA, PostgreSQL + TimescaleDB, gRPC over mTLS, no broker.
- Multi-tenant and self-hostable. Manager HA, workers per zone.
- Host capabilities `managed` (Ansible via SSH) and `monitored` (agent and/or remote checks) are independent.
- Inventory groups (Ansible, schema builder) and monitoring groups (tag selectors, alerting) are separate concepts.
- Agent config is hybrid: checks from GUI, secrets local only.
- One version and one tag for manager, worker and agent; manager accepts same and previous minor version.
- Check engine layered like Checkmk/Zabbix: plugins in code, definitions and rules as data, inheritance plugin → org → group → host → item, discovery, custom checks in Nagios or JSON format.
- Status colours (ok/warn/crit/unknown) are reserved for states; cyan is the action colour.
- GitHub repo `NoiXdev/pulsix` starts **private**; goes public with the v1.0 launch.
- Test policy: every feature ships with tests; E2E scenarios (agent, monitoring, Ansible, HA, auth, tenancy, status pages) are milestone gates; coverage enforced in CI.
