# Pulsix backlog

Planning backlog for Pulsix, the NoiXdev server management and monitoring platform.
One line per deliverable, grouped by milestone. Update the status column as work moves.

Status legend: `idea` · `mockup` · `spec` · `planned` · `in progress` · `done` · `superseded` (closed in favor of another row that covers the same ground, named in its own Notes)

The status column is only useful if it is true. `done` means the thing
ships and is covered by tests — not that a plan once named it. When part
of a row ships and part does not, the row says which part (see 1.1b,
1.12, 1.19): half-truths here cost more than an open row, because the
next person reads this table instead of the code.

## Decisions (short)

- Stack: Go (manager, worker, agent), React/TypeScript SPA, PostgreSQL + TimescaleDB, gRPC over mTLS, no broker.
- **One installation per service provider.** A provider runs their own Pulsix; their customers are organizations inside it. There is deliberately no provider entity above the organization, and resources shared across customers belong to the *installation* — the shape `instance_settings` and `instance_ca` already have. Rejected: a provider level on one shared installation. It would make every policy, role, query and navigation path carry a table with one row in the common case, and it would replace physical separation (own database, own process, own master key) with a policy predicate — a step down for a product that holds other people's SSH keys. If a multi-provider installation is ever needed, the path is a mechanical migration: add `provider_id`, backfill every instance-level row to the single provider, widen the policies. Decided 2026-10-19.
- Multi-tenant and self-hostable. Manager HA, workers per zone.
- Host capabilities `managed` (Ansible via SSH) and `monitored` (agent and/or remote checks) are independent.
- Inventory groups (Ansible, schema builder) and monitoring groups (tag selectors, alerting) are separate concepts.
- Agent config is hybrid: checks from GUI, secrets local only.
- One version and one tag for manager, worker and agent; manager accepts same and previous minor version.
- Check engine layered like Checkmk/Zabbix: plugins in code, definitions and rules as data, inheritance plugin → org → group → host → item, discovery, custom checks in Nagios or JSON format.
- Status colours (ok/warn/crit/unknown) are reserved for states; cyan is the action colour.
- GitHub repo `NoiXdev/pulsix` starts **private**; goes public with the v1.0 launch.
- Test policy: every feature ships with tests; E2E scenarios (agent, monitoring, Ansible, HA, auth, tenancy, status pages) are milestone gates; coverage enforced in CI.
