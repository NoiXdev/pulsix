## 2. Security posture

The core multi-tenant boundaries held under review: org-scoped REST authorization (`requireOrg` plus row-level security and composite foreign keys), worker and agent mTLS identity, worker claim and result binding, webhook authentication and the untrusted-variable path, and the setuid play-uid helper itself. No cross-tenant read or write by an ordinary org principal was found through the API.

The confirmed weaknesses concentrate on one theme: data from a lower-trust source reaching a higher-trust consumer without the neutralisation the code already applies elsewhere. The most serious is that host-agent facts are rendered into the worker's Ansible inventory as trusted templates, so a compromised monitored host can execute commands on the organization's zone worker during a run (high). Viewer-visible run output leaks secrets in three edge cases of the redactor (one medium, two low), agent-chosen item names can forge lines in alert notifications (low), and a pinned jump host's key is silently not enforced on mixed routes (low). On the identity side, the auth rate limiter can be bypassed with concurrent requests, removing the only brake on second-factor guessing after a password compromise (medium), and on an instance without outbound mail an invite link lets one tenant pre-create an account for someone else's address and capture that person's later invitations to other organizations (medium). The ungated `/schemas/*` route discloses the API shape the project chose to gate (low).

Eight further leads need a deployment or database fact before they can be confirmed or dismissed; they are listed separately and carry no severity.

## 4. Confirmed findings in brief

### 4.1 Agent-reported host facts are rendered as trusted Ansible hostvars, so a monitored host can run commands on the org's worker controller (high)

- **Location:** `internal/agentapi/stream.go:145` → `deploy/worker/Dockerfile:69`
- **Lower-trust principal and conditions:** The attacker holds a valid agent identity for one monitored host: root on that host, or its agent certificate and key.; The host is managed (rendered into job inventories) and a play run against it evaluates pulsix_facts, directly or through hostvars.; An operator, schedule or trigger runs such a play after the malicious facts push.
- **Reproduction:** Root on one host monitored by the Pulsix agent, sending a Facts message over that agent's own mTLS stream. In a scratch copy of the repo, a test in internal/inventory/render calls the real agents.Service.RecordFacts (fake store) with the payload fact, then render.Render for a managed host carrying the stored fact, and prints the document (golang:1.27.1-alpine, --network none, read-only, cap-drop ALL, user 65532, prescribed limits). The printed document is served by a two-line executable inventory script (#!/bin/sh; exec cat <doc>), mirroring inventoryWrapperText; a control document wraps the same value as {"__ansible_unsafe": ...}. In noixdev/pulsix-worker:dev (ansible-core 2.21.4), with --network none --read-only, the prescribed limits and --ipc private --shm-size 64m, run ansible-playbook -i <script> play.yml for both inventories.
- **Result:** RecordFacts accepted the value (err=nil) and Render emitted it raw under pulsix_facts.os. The full ansible-playbook run printed "host os is debian-42-uid65532": the arithmetic evaluated and the pipe lookup ran `id -u` in the controller process. With the __ansible_unsafe-wrapped control the same task printed the value literally.
- **Impact:** Command execution in the zone worker's Ansible controller as the run's play identity, a host-to-controller trust crossing. The play identity can read the connection material that run is given for the other hosts in its scope, enabling lateral movement within the organization.
- **Priority:** likelihood medium (Requires control of one monitored, managed host (or its agent key) and a later play that evaluates pulsix_facts, which is the variable's documented purpose. No operator credential is needed.); impact high.
- **Smallest fix:** Mark every agent-reported fact unsafe before it enters the inventory document by reusing ansiblevars.Inert (h.Facts is map[string]any, which Inert handles recursively). Add a regression test asserting that pulsix_facts strings render as {"__ansible_unsafe": ...}. Optionally also refuse '{{', '{%' and '{#' in RecordFacts as defence in depth.
- **Fingerprint:** `internal/inventory/render/render.go:hostVars:pulsix_facts-trusted-template`

### 4.2 Auth rate limit checks before the handler and charges after it, so concurrent TOTP guesses from one address get past the failed-attempt budget (medium)

- **Location:** `internal/api/mfa_handlers.go:148` → `internal/api/auth_rate_limit.go:82`
- **Lower-trust principal and conditions:** The attacker has the victim's password, or some other pending session that has not completed MFA, which is needed to reach /auth/totp/verify. Login brute force is also affected, but each attempt there costs an argon2id hash.; PULSIX_AUTH_RATE_LIMIT > 0 (default 20). The limiter is in-process, one per manager.; The requests must be in flight at the same time, before enough failures have been charged. Burst size depends only on the attacker's connections and on how many requests the server accepts and queues at once.
- **Reproduction:** A client with a pending session for an account protected by TOTP sends a burst of concurrent wrong-code verify requests from one address. Copy the repository into scratch and delete internal/api/*_test.go in the copy, because those tests import the database harness. Add the harness test there. Run go test -count=1 -v -run TestV04AuthRateLimitConcurrent ./internal/api/ in the approved Docker sandbox: golang:1.27.1-alpine, --network none, read-only source and module cache, env -i allowlist, cap-drop ALL, uid 65532, 300 s timeout. Write stdout to evidence.txt.
- **Result:** Sequential: limit=20, 50 attempts, 20 reached the handler (20x 401, 30x 429). Concurrent: limit=20, 200 attempts from one address, 198 reached the handler (198x 401, 2x 429). After the burst the next request got 429. Source: agents/v04-session-auth/artifacts/evidence.txt. This independently reproduces the hunter's result (40 of 40 against a limit of 3, with a barrier), here with the default limit, real HTTP and no barrier.
- **Impact:** It defeats the second factor on an account whose password is compromised. The result is an MFA-complete session with that user's org roles, and instance-admin rights if the user has them.
- **Priority:** likelihood low (The attacker first needs the victim's password, then must keep sending large concurrent bursts. Each guess succeeds with probability of about 3e-6, so a meaningful chance of takeover takes hundreds of thousands of guesses, spread over many one-minute windows.); impact high.
- **Smallest fix:** Reserve the attempt atomically before the handler runs: claim the slot under the limiter mutex and refund it on 2xx, 5xx or 429. Also add a per-account counter or lockout for failed second-factor attempts on /auth/totp/verify that does not depend on the client address.
- **Fingerprint:** `internal/api/auth_rate_limit.go:authRateLimitMiddleware:check-then-charge-concurrency-bypass`

### 4.3 Run-output redaction misses secrets that contain a quote or backslash together with &, < or > in ansible's display text (medium)

- **Location:** `internal/jobs/queue_sql.go:645` → `internal/api/job_handlers.go:490`
- **Lower-trust principal and conditions:** The reader needs only the viewer role (jobs.read) in the organization that ran the job.; The secret has at least one JSON-escaped character (", \ or a control character, e.g. a newline in a multi-line value) AND at least one of &, < or >.; A task's display output includes the value, e.g. debug of the var, a module result echoing it, or a failed command's output in the JSON result. This is the accidental print that redaction exists to catch.; The default ansible result_format json applies. The worker-generated ansible.cfg (layout.go ansibleCfgText) does not change it.
- **Reproduction:** An org viewer with jobs.read opens the run log, or calls the events/SSE API, for a job whose task printed a secret containing such characters. In the worker image noixdev/pulsix-worker:dev (network none, read-only, tmpfs-only writes), run ansible-runner run on a local-connection playbook with two debug tasks printing db_password=Tr&ub4dor"3x and ctrl_password=Troub4dor"3x. Capture the runner_on_ok job_event lines. Copy the repository into scratch and add a package-internal test in internal/worker/runner. It feeds those exact lines to (&Runner{}).streamEvents with newRedactor(&workerpb.Job{Redact: []string{`Tr&ub4dor"3x`, `Troub4dor"3x`}}), then decodes each forwarded payload's stdout. Run go test -run TestV17RealAnsibleDisplayRedaction ./internal/worker/runner/ in the network-less, read-only golang sandbox.
- **Result:** ansible's display stdout was ok: [localhost] => {\r\n    "db_password": "Tr&ub4dor\"3x"\r\n}. After streamEvents, the forwarded payload's stdout still read "db_password": "Tr&ub4dor\"3x" (contains secret=true), while event_data.res.db_password was [redacted]. The control secret Troub4dor"3x was [redacted] in both stdout and res. Storage and API exposure are source-verified only, because the DB-backed packages cannot run in the sandbox. Recorded in the v17-job-output run artifacts: evidence2.txt line 4 is the real ansible-runner 2.4.3 / ansible-core 2.21.4 runner_on_ok event, and evidence.txt lines 6 and 11 are the redaction outcome for the control secret and the & secret.
- **Impact:** The lowest org role reads a cleartext managed-host credential or secret var that the product explicitly withholds from viewers.
- **Priority:** likelihood low (It needs a secret with both character classes (common in generated passwords, but not universal) and a task that prints it.); impact high.
- **Smallest fix:** Add the Python json.dumps(ensure_ascii=False) spelling next to the Go one. Escape only ", \ and control characters, and leave &, <, >, U+2028/U+2029 and non-ASCII literal. A plain SetEscapeHTML(false) encoder still differs on U+2028/U+2029 and invalid UTF-8, so a hand-written escaper is the exact match. Keep the existing json.Marshal spelling. Add a regression test that feeds a recorded ansible-runner event with a secret mixing "/\ with &/</>.
- **Fingerprint:** `internal/worker/runner/redact.go:newRedactor:go-html-json-escape-vs-python-json`

### 4.4 An org owner on an instance without mail can pre-create the account for someone else's email and capture that person's later invitations from other organizations (medium)

- **Location:** `internal/api/org_handlers.go:71` → `internal/tenancy/service.go:437`
- **Lower-trust principal and conditions:** The attacker is any MFA-complete session user of the instance (able to create an org through POST /api/v1/orgs), or an admin or owner of any org.; The instance has no stored SMTP settings when the attacker creates the invite. This is the supported 'invite without mail' mode and the state after a setup that skipped mail. Mail may be configured later; the pre-created account persists.; The victim's email address has no account on the instance yet.; Another organization later invites that email address and the real person accepts the invitation.
- **Reproduction:** An MFA-complete user who owns an org on an instance without SMTP and targets a person likely to be invited later by a different tenant. Copied the repository into the verifier scratch directory and added a separate package test that imports only internal/tenancy, internal/auth and internal/mail, with no database and no testdb. Ran go test -count=1 -v -run TestV13UnmailedInvitePreHijack ./internal/v13harness/ in golang:1.27.1-alpine with --network none, --read-only, --cap-drop ALL, no-new-privileges, user 65532, 2 CPU / 2 GiB / 512 pids, env -i, GOPROXY=off, a read-only source tree and module cache, and a 300 s timeout. Checked that org B's admin membership belongs to the user ID created by the attacker's redemption, and checked which password the stored hash accepts.
- **Result:** step1 orgA invite: mailed=false accept_url_present=true; step2 attacker redeems own link: newAccount=true (the handler opens a session); step3 victim redeems orgB invite: same user ID, newAccount=false; RESULT same_user=true orgB_role_of_attacker_created_user="admin" hash_accepts_attacker_pw=true hash_accepts_victim_pw=false display_name="Victim"; --- PASS (agents/v13-invite-setup/artifacts/evidence.txt)
- **Impact:** The attacker gains the invited role, up to admin, in a foreign organization: cross-tenant access to its hosts, runs, members and credential management. The real invitee is shut out of the account that carries their address.
- **Priority:** likelihood low (Every condition must hold: the instance runs without SMTP when the attacker invites, the target email has no account yet, the attacker is already a user of the shared instance, and another tenant later invites that person, who then accepts.); impact high.
- **Smallest fix:** Never treat an account created from a link that was not mailed as an email-verified identity, and never attach a membership to an existing account on the token alone. In AcceptInvite, when the address already belongs to an account with a password, require the request to carry an MFA-complete interactive session whose user ID equals that account; otherwise refuse, without consuming the invite. Optionally, record email verification on users (set only when the link was actually mailed and redeemed) and refuse to reuse an unverified account for another org's invite. Add a regression test: an un-mailed invite redeemed by the inviter, followed by a second org's invite redeemed anonymously, must not add a membership to the first account.
- **Fingerprint:** `tenancy/AcceptInvite:unmailed-invite-link-binds-email-identity-without-mailbox-proof`

### 4.6 Host agent can inject forged lines and chat markup into alert notifications via check-result item names (low)

### 4.7 Pinned jump host's key is not enforced when its route also contains an unpinned password-only or credential-less jump host (low)

- **Location:** `internal/jobs/queue_sql.go:597` → `internal/worker/runner/sshconfig.go:179`
- **Lower-trust principal and conditions:** An organization route contains at least one bastion pinned with a full key AND at least one unpinned bastion whose credential is password-only or absent, in either order. The route can come from a host, group or zone bastion setting, or from a bastion's via-chain.; The attacker can intercept or redirect the worker's TCP connection to the pinned bastion's address. Org operators/admins configure the route in the normal way, and any run, ad-hoc command, bootstrap, rotation or revocation over it triggers the dial.

In the approved golang:1.27.1-alpine sandbox (network none, read-only source), run: go test -count=1 -v -run TestV18MixedChainPin ./internal/worker/runner/ (agents/v18-ssh-pins/artifacts/evidence.txt). - **Priority:** likelihood low (Needs a specific but supported configuration (a pinned key bastion and an unpinned bastion with a password credential or none, on the same route) plus an attacker with network position in front of the pinned bastion. - **Smallest fix:** In mergeInventory, fail the merge closed whenever a route that dials ANY pinned bastion cannot be fully aliased: a hop that cannot be scripted anywhere in the chain, a chain that does not match the claim, or a failed rewrite. Do not check only the pin of the hop that cannot be scripted. Effective args without any ProxyJump can still pass through, since they dial no bastion. Add regression tests, all expecting an error: a pinned key hop plus an unpinned password-only hop in both orders, a pinned key hop plus a credential-less hop, and a misaligned chain containing a pinned bastion.
- **Fingerprint:** `internal/worker/runner/inventory.go:mergeInventory:unaliased-jump-chain-drops-bastion-pin`

### 4.8 Base64 redaction only matches a secret at a 3-byte-aligned offset, so slurped files leak it (low)

- **Location:** `internal/jobs/queue_sql.go:647` → `internal/api/job_handlers.go:490`
- **Lower-trust principal and conditions:** Org viewer (jobs.read) reading a run's events.; A legitimate task, written by an operator or above, base64-encodes data that embeds a claim secret without no_log. Examples are slurp of a config file that holds a secret inventory var or credential, or b64encode of a templated string.; The secret's byte offset in the encoded buffer is 1 or 2 mod 3, which covers about two thirds of placements.
- **Reproduction:** An org viewer reads the events of a run whose task slurped a config file embedding a secret var. In a scratch copy of the repo, add a package-internal test in internal/worker/runner that builds newRedactor(&workerpb.Job{Redact: []string{secret}}). For each prefix ("", "a", "ab", "abc", "pwd=", "db_pass=", "password: "), build a runner_on_ok event whose event_data.res is a slurp result {content: base64(prefix+secret+"\n"), encoding: base64}. Pass it through r.eventPayload, then decode the forwarded res.content. Run go test -run TestV16Base64Alignment ./internal/worker/runner/ in the approved network-less, read-only Docker sandbox.
- **Result:** Through the real eventPayload, offsets 0 and 3 were redacted. Offsets 1, 2, 4, 8 and 10 were forwarded unchanged. For example, offset 4 forwarded cHdkPXMzY3IzdFBhc3N3MHJkCg==, and the decoded content contained s3cr3tPassw0rd (agents/v16-job-output/artifacts/evidence.txt).

## 6. Hardening notes and positive patterns

Hardening notes are not findings: each describes a missing defence-in-depth layer or a risk with no demonstrated boundary violation. They are grouped by the coverage unit whose hunter raised them.

**CI and release workflows — Build, image and release integrity**
- release.yml pushes :latest for any vX.Y.Z tag, including a later tag on an older green main commit, while compose defaults PULSIX_VERSION to latest; a backport tag would roll every :latest deployment back. Only move :latest when the tag is the highest semver. Writer-only, so not a finding.
- release.yml has no concurrency group: two tag pushes can race on :latest.
- release.yml rebuilds the images instead of promoting the CI-tested digests; the worker's apt packages and pip transitive dependencies (only ansible-core/ansible-runner are exact, nothing is hash-locked) resolve again at release time. Consider pip --require-hashes with a constraints file and promoting tested digests.
- release.yml guard queries ci.yml runs by head_sha only; adding &event=push&branch=main would stop a pull_request run (which executes the PR's own ci.yml) from counting as 'green' for a commit later on main. Tag pushing stays writer-only.
- Registry secrets are not bound to a protected GitHub environment; any workflow on a pushed branch (writer-only) could read them. A 'release' environment restricted to v* tags would narrow this.
- tag.yml's workflow_dispatch can run from any branch; the release.yml guard catches a non-main tag, but the tagging step itself has no branch check.
- Compose: the timescale/timescaledb:2.30.0-pg18 image is tag-only (traefik is digest-pinned); pin by digest for consistency.
- Compose: all services share one network, so playbooks on the worker can reach db:5432 (password-protected) and manager:8080 directly. A separate backend network for db/manager/worker-enroll would remove the reachability.
- Compose: manager's DATABASE_URL uses the schema-owner role and relies on SET ROLE pulsix_app; a RESET ROLE would restore owner rights if any SQL injection appeared. A separate login role for the app avoids this (relevant to the db peer unit).
- Compose: traefik mounts docker.sock (read-only still allows the full Docker API) and watches every container on the host; consider a socket proxy and a providers.docker.constraints/network filter.
- Compose: manager publishes ${PULSIX_HOST_PORT:-8080} on all host interfaces even when the traefik profile terminates TLS, so plaintext login on :8080 stays reachable (Docker port publishing bypasses ufw). Bind to 127.0.0.1 when behind the proxy.
- worker-enroll and the embedded worker resolve the 'default' zone across all organizations when PULSIX_WORKER_ORG is empty; if the original organization disappears and exactly one other organization has a 'default' zone, a re-enrollment attaches the bundled worker to that tenant. Default PULSIX_WORKER_ORG to the setup organization or persist the org binding in the bundle.
- install.sh accepts an http BASE_URL and the checksum comes from the same origin; refuse to render the installer for a non-https PULSIX_PUBLIC_URL (or warn on the Agents page), or sign binaries with a key the enrollment token's CA pin can verify.
- PULSIX_PUBLIC_URL is substituted into a double-quoted shell assignment by text/template without shell escaping; it is operator configuration, but rejecting '"', '$', '`' and '\\' in it would make the installer robust.

**Setuid exec helper — Privilege drop to the play uid**
- Materialize run files in a worker-private (0700) directory, or one not yet group-writable. Grant group access only at the end, with fd-relative, no-follow operations: openat/fchmodat with AT_SYMLINK_NOFOLLOW, or fchmod on an O_NOFOLLOW fd after verifying the owner is the worker uid.
- Use O_CREAT|O_EXCL|O_NOFOLLOW for run-file writes in the work dir.
- Run the play supervisor under a uid the play cannot signal (e.g. keep it at the worker uid and cross only for the runner), or have the worker sweep all play-uid processes between jobs while concurrency is 1.
- hardenIdentityDir only hardens Dir(CertPath). A KeyPath in a different directory is not covered. Harden Dir(KeyPath) as well.
- /proc/<pid>/cmdline of worker-spawned ssh/git processes exposes work dir paths to other uids. Mounting /proc with hidepid in the image or deployment would reduce what a play-uid process can observe.

**Agent enrollment and certificate renewal — Agent enroll token host binding and renew key binding**
- Agent fact keys have no length bound in agents.Service.RecordFacts (only count <= 64, non-empty, and value <= 512 bytes); a key bound would keep stored documents predictable. Availability was out of scope.
- In the bound-host enrollment flow the certificate CN and host_agents.agent_name come from the presenter (1-64 runes, any characters) and appear in audit summaries; a charset rule like hostNamePattern would keep audit text clean.
- The prescribed sandbox recipe copies /scratch with docker cp after the container exits, but tmpfs contents are discarded on stop, so the copy is always empty. Evidence here was captured by printing the tmpfs file to stdout through docker start -a, with every control unchanged.

**Agent stream facts (fact-sourced tags) — Fact-sourced host tags consumed by selectors**
- alert_events.alert_id is a single-column FK to alerts(id) (internal/db/migrations/00049_alerts.sql), and the follower's UndecidedAlertEvents/HeldAlertEvents join alerts and hosts on id alone (internal/db/queries/alert_routes.sql). Today every writer keeps org_id consistent, but a composite FK (org_id, alert_id) -> alerts(org_id, id) plus a.org_id = ae.org_id in those joins would make the follower's tenant binding schema-enforced rather than writer-enforced.
- UpsertHostFacts merges with jsonb || and never removes keys (internal/db/queries/agents.sql), so an agent that rotates through new fact keys on each push can grow hosts.facts without bound (64 keys x 512 bytes per push). This is an availability concern under the deferred resource-exhaustion unit, not an access-control finding.
- Once a manual tag overrides it, a stale fact tag row stays in host_tags. Both SQL selector consumers hide it with the manual-first CTE, but any future raw selector.SQL caller that skips the CTE would let an agent-controlled os/arch/virt value match. Consider deleting the fact row when a manual tag of the same key is written, or documenting the CTE requirement as an enforced helper.

**Agent check results — Notification payload rendering**
- Outbound webhook policy allows RFC1918/ULA/CGNAT by design (spec v0.2c section 5). On a multi-tenant instance this lets any org admin send blind POST/PUT requests, with chosen headers, Content-Type and literal body, to the manager's own compose network (other containers, the Docker host gateway, internal admin UIs). Consider an instance setting to block private ranges for org-defined channels and allow only PULSIX_NOTIFY_ALLOW_CIDRS.
- Delivery last_error keeps the transport cause after redactURL, e.g. 'dial tcp 172.18.0.3:5432: connect: connection refused' or 'the endpoint answered 404'. It is shown to channels.read (operator) and returned synchronously by the test endpoint, which gives a port and HTTP-path oracle into the internal network. Consider generic error classes for refused, timeout and status-code outcomes.
- The approved sandbox recipe's 'docker cp' from the /scratch tmpfs after the container exits returns nothing, because tmpfs is discarded on stop. Evidence here was captured from container stdout instead; the parent's hunter template should be adjusted.

**Org-scoped REST routes — Org membership, role and token authorization**
- notification channel update keeps stored webhook header values and the signing secret when the URL is changed (internal/api/notify_dto.go 'Omit on update to keep'). An admin with channels.write could point an existing channel at a new host and receive the write-only header values. This is admin-only and admins already hold credentials.read, so it is not a boundary crossing, but re-requiring secret values on a host change would close the write-only-secret read-back.
- tenancy.Service.DeactivateUser runs DisableUser, RevokeSessionsForUser and RevokeTokensForUser as three separate statements outside WithInstanceTx. A failure between them leaves a partly revoked user. GetSession and GetAPITokenByHash also check disabled_at, so access is still denied, but wrapping the three in one instance transaction would make it atomic.

**Login and session cookie — Session issuance, lookup and invalidation**
- huma v2.39.1 api.Unmarshal treats an empty Content-Type as application/json, so a typeless-Blob no-cors fetch can send JSON bodies without preflight; with no CSRF token or Origin check, only SameSite=Lax stops cookie-authenticated mutations, leaving same-site sibling origins able to drive them. Add an Origin/Sec-Fetch-Site check on cookie-authenticated mutations and require Content-Type: application/json.
- Rename the session cookie to __Host-pulsix_session (Secure deployments) to prevent sibling-host cookie tossing.
- Sessions are not revoked when a factor is removed or replaced (passkey delete, TOTP re-enrol/disable) and there is no sign-out-other-sessions action; a session opened with a since-revoked passkey stays valid up to the 12 h absolute TTL.
- SecondFactors.DisableTOTP and DeletePasskey each check the other factor then delete without a transaction or lock, so two concurrent requests can remove both factors; no privilege gain because both require a fresh MFA-complete session, but it breaks the at-least-one-factor invariant.
- POST /auth/totp/confirm does not call requireFreshFactor; currently harmless because a pending secret can only be created through the fresh-gated enrol, but the two ends of the TOTP ceremony are gated inconsistently compared with passkey register begin/finish.

**Public webhook receivers — Untrusted webhook values reaching Ansible**
- internal/ansiblevars/untrusted.go Inert wraps only string VALUES. Object keys inside a mapped webhook object (for example {"{{ lookup('pipe','id') }}": 1}) reach the extra-vars file unwrapped and pass CheckUntrusted. Safety rests on the in-code assertion that Ansible never templates dictionary keys, and nothing in the repository verifies that for ansible-core 2.21.4 (the real-Ansible tests in internal/worker/runner/unsafe_test.go cover values only). A playbook that turns keys into values (dict2items, set_fact from a sender object) widens the exposure. Cheap fix: have CheckUntrusted refuse keys containing '{{', '{%' or '{#'.
- internal/triggers/auth.go and receive.go do not deduplicate deliveries. A captured signed request (for example from a sender's delivery log or a TLS-terminating hop) re-runs the template with the same values within the 5-minute window, or indefinitely for the github, gitea, gitlab and bearer presets and for pulsix without a timestamp header. Optional dedupe on the sender's delivery id (X-GitHub-Delivery, X-Gitea-Delivery, X-Gitlab-Event-UUID) would close this.
- internal/triggers/service.go Update can remove timestamp_header without rotating the secret. A request captured while the timestamp was on (sig = HMAC('<ts>.<body>')) then verifies as an untimestamped delivery whose body is the literal '<ts>.<body>'. With an empty mapping that starts a run; a non-empty mapping answers 422 because the body is not JSON. Fix: rotate the secret, or domain-separate the MAC input, when the timestamp mode changes.
- internal/jobs/queue_sql.go and run_request.go: a webhook-mapped limit REPLACES the template's own limit instead of intersecting it, so a sender whose mapping targets limit can send '*' (or an empty string) and widen the run to the template's whole resolved scope. This follows the spec, since the operator opted into the limit mapping, but intersecting ('<template limit>:&<webhook limit>') would keep the template's narrowing.
- internal/triggers/receive.go: the per-IP hook limiter is consulted after the full check and replaces only the hidden 404 outcomes with 429; a correct secret still answers 202 once the budget is spent. It throttles probing for trigger ids, not secret guessing. The 256-bit secret makes this moot, but the comment 'cannot probe ids or secrets at will' overstates it.

**Job run output, events, stats and error text — Redaction of secrets from viewer-readable job output**
- internal/api/job_sse.go writeJobStream never re-checks membership or token validity after requireOrg. A member removed (or token revoked) mid-run keeps receiving that one job's events until it ends. Re-run the org/permission check on the 500 ms status tick.
- internal/worker/loop.go report sends execErr.Error() and executor stats without passing them through the claim's redactor. No current path puts a secret there, but applying newRedactor's text() to errText would make the guarantee structural (ansible-galaxy stderr, for example, is forwarded verbatim from repo-controlled requirements).
- Values decrypted from Ansible Vault files in a repository are never known to the manager and so are never redacted. Document that vaulted vars need no_log, or surface that limitation in the run view.
- minRedactLen (4) leaves 1-3 character secrets unredacted by design. Consider refusing such secret values at write time instead.

**Invite acceptance — Invite token to account and membership binding**
- First-run setup (POST /api/v1/setup/complete) is first-caller-wins with no setup token. A fresh instance reachable from the network before the operator finishes the wizard can be claimed by anyone. This is documented as design; consider a one-time setup token printed to the manager log.
- PUT /api/v1/admin/settings/smtp keeps the stored, write-only SMTP password when the password field is absent, even if host changes. An instance admin, or a hijacked admin session, can repoint the host to a server with a valid certificate for that name and receive the sealed password through AUTH PLAIN. Consider clearing or requiring re-entry of the password when the host changes.
- AcceptInvite adds a membership to a disabled account (GetUserByEmail does not filter disabled_at). This is harmless because sessions for disabled users never resolve, but it is untidy; consider refusing.
- AcceptInvite hashes the submitted password (argon2id) even when the address already has an account and the hash is discarded. Hashing before the existing-account check wastes CPU on the public, rate-limited route.

**Repository and shared-repository definitions — Repository URL, branch and subpath validation**
- Shared repo definitions (internal/shared/service.go CreateRepo/UpdateRepo, internal/api/shared_handlers.go repoDefinitionBody) skip repos.validateURL and the branch/subpath patterns and check length only. The writer is the instance admin, but reusing the same validator would stop malformed values from reaching every org's projection. It would also prevent a projection with an invalid stored value from blocking org-side credential edits, because Update validates before refuseSharedFieldChange.
- sync_repo's findRequirements joins the unvalidated Subpath without safeSubpath. Org repos are protected by the manager's no-'..' rule, but shared definitions are not; apply safeSubpath in SyncExecutor.Run as well.
- The worker git invocations set no protocol allowlist. Setting GIT_ALLOW_PROTOCOL=https:ssh (or -c protocol.allow=never plus explicit allows) would make the remote-helper and file:// cases fail closed rather than depend on git defaults.
- ansible-galaxy runs with cwd set to the repository clone, so a repo-supplied ansible.cfg is loaded as the worker uid (log_path, local_tmp, galaxy cache/token paths). Set ANSIBLE_CONFIG to a worker-owned file, or run galaxy from the work dir.

**gRPC interceptor — Client certificate to worker or agent principal**
- internal/grpcsrv/server.go tokenRegistry.consume compares the RunEvents binding token with a plain string != and the binding is keyed by job id only, not by the claiming worker id; RunEvents (internal/grpcsrv/events.go) never checks that the authenticated worker is the job's claimant. Not exploitable as-is (128-bit crypto/rand token delivered only to the claimant over mTLS, single-use, 30 s TTL), but storing the worker id in boundToken, comparing it in consume, and using subtle.ConstantTimeCompare would bind the stream to the channel identity defensively.
- internal/grpcsrv/streams.go StreamRegistry and the claim tokenRegistry are in-process; with several managers a revocation only cuts RunEvents streams on the manager that handled it. Multi-manager HA is a future (v0.6) item; revisit before HA ships.
- RenewCertificate is unthrottled and each call adds a still-valid worker_certificates row (old certificates stay valid until expiry); bound to the same key so no persistence gain, but a per-worker renewal rate limit or revoking superseded serials would shrink the valid-serial set.

**Worker claim and result report — Claim scope and result binding**
- ClaimJob (internal/grpcsrv/claim.go) does not re-check the worker's registry status after the claim commits, unlike RunEvents' track-then-lookup; a revocation committing between the interceptor lookup and the ClaimJob UPDATE still ships one decrypted payload to the revoked worker. Add a status predicate (join workers.status = 'active') to the ClaimJob UPDATE or a post-claim lookup that fails the job closed.
- The production gRPC event path calls SQLQueue.AppendEvent (unbound), not boundStream.Append, so an event is stamped with the job's newest live binding's attempt or the row's current attempt rather than the attempt its stream was claimed under (backlog 2.49 intent), and events keep landing after the job is terminal. Route the gRPC append through the claim's binding.
- job_events seq is assigned from max(seq) WHERE at >= created_at, while at is worker-supplied; an event dated before the job's creation is invisible to that subquery, producing duplicate seqs (the PK includes at). Clamp at to [created_at, now+skew] on append.
- FinishFor's idempotent onMiss returns nil for an already terminal job of the same worker, so ReportResult records a fresh job.result audit row with a status the row does not carry (e.g. 'succeeded' after the reaper failed it). Skip the audit write when the transition was not applied.
- tokenRegistry.consume compares the binding token with != rather than subtle.ConstantTimeCompare; low value given 128-bit single-use tokens but trivial to harden.

**Shared definitions projected into every organization — Installation-level definitions vs org-owned projected rows**
- Add UNIQUE (org_id, repo_id, path) WHERE source = 'repo' on playbooks (additive; dedupe first) or make playbooks.Service.CreateRepo refuse a duplicate path, and rewrite InsertProjectedTemplates with a LATERAL (... ORDER BY pb.id LIMIT 1) lookup so the bulk projection cannot fan out on org data; also make the scalar LIMIT 1 lookups deterministic with ORDER BY.
- Org-creation projection (ProjectAllInto/ProjectAllTemplatesInto/ProjectAllCheckDefinitionsInto) runs after the org commit; a definition created concurrently can list organizations before the new org commits while the hook reads definitions before the definition commits, leaving that org permanently without the projection. No reconciliation pass exists for projections (only for default zones). Integrity of provider-distributed resources, not a tenant boundary.
- Changing a shared repository's URL propagates to every projection while each org's own git credential stays attached (only the host-key pin is cleared), so the instance admin can redirect org git credentials to a new server; acceptable given instance-admin trust but worth documenting for operators.

**Managed-host and jump-host SSH connections from the worker — Host-key pin enforcement on every SSH path**
- internal/jobs/system_claim.go:321 claimBastionKeys returns no pins when the bastion pin source is nil, while claimHostKeys (queue_sql.go:813) fails closed for the same wiring gap; production wires hostsSvc (internal/app/app.go:412), so this is wiring-only, but it should fail closed for symmetry.
- internal/worker/runner/sshconfig.go:155-163 makes 'Host *' accept-new even when the claim carries pins; once the remediation lands, a defensive option is to render the catch-all as StrictHostKeyChecking yes whenever any bastion pin is present, so any future unaliased path to a pinned address fails closed rather than trusting on first use.
- internal/worker/runner/inventory.go:379-408 pinBastions writes pin lines for bastions that the merged chain no longer references by alias; cross-checking that every pinned bastion in use received an alias block would detect this class of drift at materialization time.

**Whole repository — Secrets, debug gating and basic exposure**
- No dependency vulnerability scan (govulncheck / npm audit) runs in .github/workflows/ci.yml. Known-CVE status of go.sum and package-lock.json was not checked offline.
- GET /healthz discloses the exact build version to anonymous callers (internal/api/api.go). Consider dropping the version or gating it.
- The explorer CSP allows the whole of https://cdn.jsdelivr.net for script-src. SRI pins the one tag, but any injection on that page could load arbitrary jsdelivr-hosted code. Pin to the exact package path.
