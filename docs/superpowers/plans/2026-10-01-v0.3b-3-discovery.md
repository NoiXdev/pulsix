# Pulsix v0.3b-3 Discovery and Item Decisions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the things a check measures — mounts, service units — become rows the product knows about, and an operator can decide that one of them should not be judged, as a single item or as a pattern, with a host able to overrule the organization.

**Architecture:** A new leaf package `internal/items` owns two tables and one pure resolution: `check_items` is written by the evaluation ticker (`ON CONFLICT DO NOTHING`, once per item ever), `check_item_decisions` is written by operators. The ticker resolves decisions per item while it already holds the host's data, skips an ignored tuple exactly as it already skips one with no resolved interval, and deletes that tuple's stored state row. "Ignored" never becomes a fifth state: the read side resolves the same decisions through the same function.

**Tech Stack:** as v0.3b-2 (Go 1.27, chi v5, huma v2, pgx v5, sqlc, goose, testcontainers-go, React 19, TanStack, Vitest, Playwright). **No new dependency in either half** — the glob is a dozen lines, not a library.

**Spec:** `docs/superpowers/specs/2026-10-01-v0.3b-3-discovery-design.md` (binding for every decision below).

## Review Focus

The input classes the spec implies but that no single task's own tests would otherwise exercise. Each has its pinning test assigned to the task that owns the code.

1. **A pattern of `*`.** Nothing prevents an operator muting the whole fleet; the preview's true match count, shown before saving, is the only brake there is (Task 3).
2. **Ignoring an item that already has a state row.** The row goes, and the interface says "ignored" rather than "not yet evaluated" — two different statements, and conflating them is the lie this milestone's predecessor went out of its way to avoid (Tasks 5 and 8).
3. **A decision that predates its item.** When the item appears it must be ignored from the first tick, not after a round (Task 4).
4. **An organization pattern and a host `watch` on the same item.** The host wins, and the view says why (Tasks 1 and 6).
5. **Two equally specific patterns both matching.** The same winner every time, from the total order rather than from map iteration (Task 1).
6. **The ignored item is the host's only `crit`.** The host turns green in the same tick, and the fleet's counts agree with the host page (Task 5).
7. **`first_seen` after a gap.** A mount gone two weeks and back is the same item; the timestamp must not jump (Task 2).

### Task 1: The glob and the decision resolution

**Files:** create `internal/items/glob.go`, `internal/items/decide.go`, `internal/items/glob_test.go`, `internal/items/decide_test.go`.

**Interfaces — Produces:**
```go
type Scope string

const (
    ScopeOrg  Scope = "org"
    ScopeHost Scope = "host"
)

type MatchKind string

const (
    MatchExact MatchKind = "exact"
    MatchGlob  MatchKind = "glob"
)

type Verdict string

const (
    Ignore Verdict = "ignore"
    Watch  Verdict = "watch"
)

// Match reports whether pattern matches item. '*' matches any run of
// characters, including none; every other character is a literal; the
// match is anchored at both ends. That is the whole syntax.
func Match(pattern, item string) bool

// MaxPatternLen bounds a pattern so neither the matcher nor a LIKE
// translation can be handed something unbounded.
const MaxPatternLen = 512

// ValidPattern refuses an empty pattern and one past MaxPatternLen.
func ValidPattern(p string) error

type Decision struct {
    ID, OrgID            uuid.UUID
    Scope                Scope
    HostID               *uuid.UUID
    CheckKey             string
    MatchKind            MatchKind
    Pattern              string
    Verdict              Verdict
    Note                 string
    CreatedBy            *uuid.UUID
    CreatedAt, UpdatedAt time.Time
}

// Target names one item a decision can be about.
type Target struct {
    HostID   uuid.UUID
    CheckKey string
    Item     string
}

// Resolution is what Decide concluded, and the decision that concluded it.
type Resolution struct {
    Verdict  Verdict
    Decision *Decision // nil when nothing matched
}

// Ignored is the question the evaluator actually asks.
func (r Resolution) Ignored() bool

// Decide picks the decision governing t. Host beats org; within a scope,
// exact beats glob; a remaining tie goes to the older CreatedAt, then the
// smaller ID byte for byte — the same strict total order rules.Resolve
// implements, for the same reason. With no match the verdict is Watch and
// Decision is nil.
func Decide(ds []Decision, t Target) Resolution

var ErrInvalidInput = errors.New("invalid input")
```

`Verdict` is the Go name for the column the spec and the migration call
`decision` — the column keeps its name, because "decision" is the word an
operator uses, while `Decision` is already taken in Go by the row itself.
Do not rename either to match the other.

`Match` is implemented by splitting the pattern on `*` and walking the literals in order: the first segment must prefix, the last must suffix, and the middle ones must appear in sequence. No regular expression, no backtracking, so a pattern of a hundred stars cannot cost more than linear time.

`Decide` filters by `CheckKey` and by scope applicability (`ScopeHost` decisions only when `HostID` equals the target's) before ranking, and never mutates the slice it is given — it is called from inside the evaluation path.

**Tests:** the glob exhaustively — exact match; `*` alone; leading, trailing and interior `*`; several stars; a pattern that is only stars; an empty item; a pattern whose literals appear out of order (must not match); and literals that would be metacharacters in a richer syntax (`.`, `?`, `[`, `\`, `%`, `_`) asserted to match themselves and nothing else. `ValidPattern` on empty and over-long input. `Decide` as a table: no decisions; one org glob; one org exact; host beats org (**review focus 4**, with the host's verdict `Watch` over the org's `Ignore`, asserting both the verdict and which decision is reported); exact beats glob within a scope; a decision for another check key ignored; a `ScopeHost` decision for another host ignored; and two equally specific matching globs resolved the same way over a hundred shuffles of the input slice (**review focus 5**), comparing the whole `Resolution` rather than just the verdict.

Commit: `feat(items): the item glob and the decision that governs an item`.

### Task 2: Migration 00048 + the items store

**Files:** create `internal/db/migrations/00048_check_items.sql`, `internal/db/queries/items.sql`, `internal/items/store_sql.go`, `internal/items/store_sql_test.go`; modify nothing else.

**Interfaces — Consumes:** `Decision`, `Scope`, `MatchKind`, `Verdict` (Task 1).
**Interfaces — Produces:**
```go
type Item struct {
    OrgID, HostID  uuid.UUID
    CheckKey, Item string
    FirstSeen      time.Time
}

// Seen is one item the ticker observed on a host this tick.
type Seen struct {
    CheckKey, Item string
}

// View is an item plus what the read side needs: when it was last
// reported, which is max(at) over that tuple's check_current rows and is
// therefore never stored.
type View struct {
    Item
    LastSeen time.Time
    Reported bool
}

type Filter struct {
    CheckKey string
    ItemGlob string // the same one-character glob Match implements
}

type Store interface {
    // Discover inserts every item of items it has not seen before, and
    // leaves an existing row exactly as it is — first_seen must not move.
    Discover(ctx context.Context, orgID, hostID uuid.UUID, items []Seen) error
    ItemsForHost(ctx context.Context, orgID, hostID uuid.UUID) ([]View, error)
    ItemsForOrg(ctx context.Context, orgID uuid.UUID, f Filter) ([]View, error)

    Decisions(ctx context.Context, orgID uuid.UUID, hostID *uuid.UUID) ([]Decision, error)
    CreateDecision(ctx context.Context, d Decision) error
    UpdateDecision(ctx context.Context, d Decision) error
    DeleteDecision(ctx context.Context, orgID, id uuid.UUID) error
    GetDecision(ctx context.Context, orgID, id uuid.UUID) (Decision, error)
    ListDecisions(ctx context.Context, orgID uuid.UUID) ([]Decision, error)
}

func NewSQLStore(d *db.DB) *SQLStore
```

Both tables exactly as the spec's data model, with substantial explanatory comments in the style of `00045_check_rules.sql` and `00046_check_states.sql` — those are the standard, and a comment saying *why* a constraint exists is the point. `check_items` carries `first_seen` and no `last_seen`; say in the comment that storing it would mean one write per item per host per tick and that `check_current` already holds it. `check_item_decisions` gets the `CHECK` tying `scope` to `host_id` in the shape `check_rules` uses, plus the RLS pair on both tables.

`ItemsForOrg`'s glob filter is translated to a SQL `LIKE`: `*` becomes `%`, and `%`, `_` and the escape character in the operator's pattern are escaped so they stay literals. Our glob is a strict subset of `LIKE`, which is what makes the translation exact — say so in the query's comment, because the next person will wonder whether it drifts.

`Decisions(ctx, orgID, hostID)` returns the organization's decisions plus, when `hostID` is non-nil, that host's — one query, since the evaluator calls it per host and must not pay per item.

**Tests:** integration against `internal/db/testdb`. `Discover` inserts, then a second `Discover` of the same items leaves `first_seen` untouched (**review focus 7**, asserted by reading the timestamp back and comparing, not by row count). An item seen, absent for a simulated gap, then seen again keeps its original `first_seen`. `ItemsForHost` reports `LastSeen` from `check_current` and `Reported: false` for an item with no current row. `ItemsForOrg` under each filter and under none, including a glob with `%` and `_` in it asserted to match those characters literally. The `CHECK` rejecting each wrong `scope`/`host_id` combination. Both RLS pairs through `d.WithOrg`. Cross-org isolation on every read.

Commit: `feat(items): discovered items and operator decisions in the schema`.

### Task 3: The decisions service and the preview

**Files:** create `internal/items/service.go`, `internal/items/service_test.go`.

**Interfaces — Consumes:** Tasks 1 and 2.
**Interfaces — Produces:**
```go
type DecisionInput struct {
    Scope     Scope
    HostID    *uuid.UUID
    CheckKey  string
    MatchKind MatchKind
    Pattern   string
    Verdict   Verdict
    Note      string
}

// Preview is what a pattern would catch. Matches is capped; Total is not,
// because the count is the only brake on a pattern that catches the fleet.
type Preview struct {
    Matches []Target
    Total   int
    Capped  bool
}

const PreviewLimit = 200

func NewService(store Store, opts ...Option) *Service
func WithClock(now func() time.Time) Option
func WithRand(r io.Reader) Option

func (s *Service) CreateDecision(ctx context.Context, orgID uuid.UUID, in DecisionInput) (Decision, error)
func (s *Service) UpdateDecision(ctx context.Context, orgID, id uuid.UUID, in DecisionInput) (Decision, error)
func (s *Service) DeleteDecision(ctx context.Context, orgID, id uuid.UUID) error
func (s *Service) GetDecision(ctx context.Context, orgID, id uuid.UUID) (Decision, error)
func (s *Service) ListDecisions(ctx context.Context, orgID uuid.UUID) ([]Decision, error)

// Preview reports which known items in would govern, without storing it.
func (s *Service) Preview(ctx context.Context, orgID uuid.UUID, in DecisionInput) (Preview, error)

// ItemsForHost and ItemsForOrg pass through, so the API has one dependency.
func (s *Service) ItemsForHost(ctx context.Context, orgID, hostID uuid.UUID) ([]View, error)
func (s *Service) ItemsForOrg(ctx context.Context, orgID uuid.UUID, f Filter) ([]View, error)

var ErrNotFound = errors.New("not found")
```

Validation: `scope` decides whether `HostID` must be set (set exactly for `ScopeHost`, nil otherwise); `check_key` must be one the catalogue knows, so a decision cannot name a check that does not exist; `MatchExact` requires a pattern with no `*` in it (an exact decision whose pattern contains a star is a user who meant `glob`, and refusing it with that message is kinder than silently matching nothing); `ValidPattern` for both kinds; `note` at most 500 characters; `Verdict` one of the two.

**`Preview` is the brake, so it reports the truth about size.** It resolves the proposed decision against every known item of the organization — or of the host, when the input is host-scoped — returns at most `PreviewLimit` of them, and sets `Total` to the full count with `Capped` when it exceeded the limit. A caller must be able to render "this would match 4 182 items" without the service having built a list that long in memory.

**Tests:** the validation table against a fake store, every rule above, each asserting the message as well as the sentinel. Cross-org `ErrNotFound`. `Preview` over a seeded item set: an exact pattern matching one; a glob matching several; a glob matching none; and **review focus 1** — a pattern of `*` over more than `PreviewLimit` items, asserting `Total` is the true count, `Capped` is true, and `len(Matches) == PreviewLimit`. A test that `Preview` writes nothing, by listing decisions before and after.

Commit: `feat(items): the decisions service and the preview that bounds a pattern`.

### Task 4: Discovery and decision loading in the ticker

**Files:** modify `internal/rules/load_sql.go`, `internal/rules/evaluate.go` (the `Snapshot` field only), `internal/rules/due_sql.go`, `internal/rules/due_sql_test.go`, `internal/app/app.go`, `internal/app/rules_ports.go`.

**Interfaces — Consumes:** `items.Decide`, `items.Decision`, `items.Target`, `items.Seen`, `Store.Discover`, `Store.Decisions` (Tasks 1–2).
**Interfaces — Produces:**
```go
// On rules.Snapshot, beside the existing fields:
//   Ignored map[ItemKey]bool
//
// Ignored is resolved by Load, not by Evaluate: the evaluator stays pure
// and keeps no dependency on internal/items. An absent key means watched.
```

`Load` already reads the host's current tuples. From them it builds the `[]items.Seen` of every **non-empty** item — `cpu` and `memory` report an empty item and are not things to discover — and calls `Discover` in the same per-host transaction `Apply` uses. It then calls `Decisions(ctx, orgID, &hostID)` once and runs `items.Decide` per distinct `ItemKey`, filling `Snapshot.Ignored`.

`internal/rules` imports `internal/items` directly: `items` is a leaf that imports neither `rules` nor `checks`, so no cycle and no adapter. `internal/app` wires the items store into the evaluation store's constructor.

**Tests:** integration. A host with two mounts gets two `check_items` rows and no row for its `cpu` reading. **Review focus 3:** a decision created *before* any item exists, then the item appears — the first evaluation after it appears must already see `Ignored` true, proving the resolution is per tick and not seeded once. A decision for another host does not leak into this host's `Ignored`. Unit tests for the `Seen` derivation (empty items dropped, duplicates collapsed) against a fake store.

Commit: `feat(rules): discover a host's items and resolve what to ignore`.

### Task 5: Evaluation skips an ignored tuple and drops its state

**Files:** modify `internal/rules/evaluate.go`, `internal/rules/evaluate_test.go`, `internal/rules/due_sql.go`, `internal/rules/states_store.go`, `internal/db/queries/rules.sql`, `internal/rules/due_sql_test.go`.

**Interfaces — Consumes:** `Snapshot.Ignored` (Task 4).
**Interfaces — Produces:**
```go
// On rules.Result, beside the existing fields:
//   Dropped []Tuple
//
// Dropped lists the tuples whose stored check_states row must be deleted
// because nothing judges them any more. Evaluate decides; Apply deletes.
// This is the one place an ignored tuple differs from a tuple with no
// resolved interval, which deliberately leaves its row standing: an
// operator who ignores a crit volume must not be left with a row that
// still says crit because nothing re-judged it.
```

In `Evaluate`, a tuple whose `ItemKey` is in `Ignored` is skipped exactly where a tuple with no resolved interval is skipped — the same guard, one more condition — so it produces no state, contributes nothing to the roll-up, and sets no due time. If `Previous` holds a state for it, its `Tuple` goes into `Dropped`.

`Apply` deletes those rows inside the claim's transaction, before it writes the states it did produce. A dropped tuple writes **no** `check_state_changes` row: that table holds states, and "no longer judged" is not one — the audit log carries the decision, with its reason.

**Tests:** table rows in `evaluate_test.go`. An ignored tuple with no previous state produces nothing and no `Dropped` entry. **Review focus 2:** an ignored tuple whose `Previous` holds `crit` produces no state and exactly one `Dropped` entry, and writes no `Change`. **Review focus 6:** a host with one ignored `crit` and three `ok` tuples rolls up to `ok` with the crit count at zero — asserting the whole `Result`, including `NextDue`, so an ignored tuple cannot smuggle in a wake-up. Integration in `due_sql_test.go`: `Apply` really removes the row, and re-watching the item on a later tick re-creates it with `Since` set to that tick rather than to the original crossing.

Commit: `feat(rules): an ignored item is judged by nobody, and keeps no verdict`.

### Task 7: GUI — the Items tab, the pattern editor and its preview

**Files:** create `web/src/features/checks/ItemsPage.tsx`, `web/src/features/checks/ItemDecisionDialog.tsx`, their `.test.tsx` siblings, `web/src/api/hooks/useItems.ts`; modify `web/src/features/checks/ChecksTabs.tsx`, the route table.

A fourth tab beside Checks, Monitoring groups and Rules. The list shows each decision's scope and target, its check, its pattern, its verdict, its note and when it was made, grouped so an organization-wide pattern reads as the broad stroke it is.

The dialog is the pattern editor. As the operator types, it previews against `POST /item-decisions/preview` on a debounce and shows **the true total**, not the length of the returned list — "matches 4 182 items" is the sentence that stops someone saving `*`. Above a threshold the dialog requires an explicit second confirmation before saving, in the same spirit as the one-way mode switch the rule editor already has. The note field is prominent rather than tucked away: it is what the next operator reads.

**At organization scope the dialog does not offer `watch`.** Watching is
already what happens by default, so an organization-wide `watch` changes
nothing — offering it would promise an effect it cannot have. It stays
available at host scope, which is the overrule it exists for, and the
dialog says so in one line rather than leaving the absence to be puzzled
over.

Follow `RulesPage.tsx` and `RuleDialog.tsx` — this tab is their sibling and must read as one.

**Tests (Vitest):** the list renders and groups; creating a decision sends the expected body; the preview debounces and renders the true total rather than the capped list length; the verdict control offers `watch` at host scope and not at organization scope; a pattern matching more than the threshold demands the second confirmation and does not save without it; an exact pattern containing `*` surfaces the API's own message; a failed save shows the API's message rather than a generic one (backlog 2.85's recorded lesson).

Commit: `feat(web): the items tab and the pattern editor that shows what it catches`.
