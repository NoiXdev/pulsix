# v0.4b Alert Routes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect monitoring alerts to the notification channels Pulsix already delivers through, so that an alert can reach a person.

**Architecture:** A new package `internal/alertroutes` holds route configuration, a pure resolver, and a ticker that follows `alert_events`. The ticker decides each event once, records the decision in a ledger whose primary key is the idempotency, and hands batches to the existing outbox. `internal/notify` gains a generic exported door and one new message kind; `internal/alerts` gains one exported enum; neither depends on the new package.

**Tech Stack:** Go 1.27.1 (pinned), pgx v5, sqlc, goose, huma v2, chi v5, React 19, TanStack Query/Router, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-v0.4b-alert-routes-design.md`

## Review Focus

Five things the spec implies that no task's own happy-path tests would exercise. Each line's test is written into the task that owns the code.

1. **A route scoped to a monitoring group in another organization must never match.** Cross-tenant leakage through a route's scope target is the worst outcome this package can produce. → Task 6, RLS test, and Task 4, `Match` with a foreign group id.
2. **A disabled route must not match even when scope, severity and event all agree.** `enabled` is the operator's off switch and must be checked before anything else. → Task 4.
3. **An event whose severity matches but whose kind no route selected must be recorded `unrouted`, not left undecided.** Otherwise the anti-join re-examines it every tick forever. → Task 8.
4. **Two managers ticking the same organization at once must produce one message, not two.** The advisory lock is the only thing preventing it. → Task 9.
5. **A channel deleted between resolution and enqueue must not fail the whole tick.** One operator deleting a channel must not stop every other channel's alerts. → Task 9.

```sql
-- +goose Up
-- v0.4b (spec docs/superpowers/specs/2026-10-12-v0.4b-alert-routes-
-- design.md, "Data model"): routes say which alert reaches which
-- notification channel. Routes ADD UP rather than override — backlog
-- 4.1b's own ruling — so there is no precedence column here and no
-- tie-break: every matching route contributes its channels, and the
-- union is taken in Go.
--
-- The scope target is two typed columns rather than one polymorphic
-- scope_id, because the spec promises that a route dies with the group
-- or host it points at and one column cannot carry a foreign key to two
-- tables. Both targets already offer UNIQUE (org_id, id) — monitoring
-- groups since 00042, hosts since 00014 — so the cascade is real rather
-- than something the application has to remember. The CHECK is what
-- keeps the pair honest: exactly one target for a scoped route, none at
-- all for an organization-wide one. The Go side still sees a single
-- optional ScopeID; the store maps it to the right column.
CREATE TABLE alert_routes (
  id             uuid PRIMARY KEY,
  org_id         uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  name           text NOT NULL,
  enabled        boolean NOT NULL DEFAULT true,
  scope          text NOT NULL CHECK (scope IN ('org', 'monitoring_group', 'host')),
  scope_group_id uuid,
  scope_host_id  uuid,
  revision       bigint NOT NULL DEFAULT 1,
  created_at     timestamptz NOT NULL,
  updated_at     timestamptz NOT NULL,
  UNIQUE (org_id, name),
  UNIQUE (org_id, id),
  FOREIGN KEY (org_id, scope_group_id) REFERENCES monitoring_groups (org_id, id) ON DELETE CASCADE,
  FOREIGN KEY (org_id, scope_host_id) REFERENCES hosts (org_id, id) ON DELETE CASCADE,
  CONSTRAINT alert_routes_scope_target CHECK (
    (scope = 'org'              AND scope_group_id IS NULL     AND scope_host_id IS NULL) OR
    (scope = 'monitoring_group' AND scope_group_id IS NOT NULL AND scope_host_id IS NULL) OR
    (scope = 'host'             AND scope_group_id IS NULL     AND scope_host_id IS NOT NULL)
  )
);

-- The three selection tables. One row per chosen value, rather than an
-- array column, so that a foreign key can hold for the channel and so
-- that "which routes send to this channel" is an index lookup.
CREATE TABLE alert_route_severities (
  org_id   uuid NOT NULL,
  route_id uuid NOT NULL,
  severity text NOT NULL CHECK (severity IN ('warn', 'crit', 'unknown')),
  PRIMARY KEY (route_id, severity),
  FOREIGN KEY (org_id, route_id) REFERENCES alert_routes (org_id, id) ON DELETE CASCADE
);

CREATE TABLE alert_route_events (
  org_id   uuid NOT NULL,
  route_id uuid NOT NULL,
  kind     text NOT NULL CHECK (kind IN ('opened', 'severity_raised', 'acknowledged',
                                         'ack_voided', 'snoozed', 'unsnoozed', 'closed')),
  PRIMARY KEY (route_id, kind),
  FOREIGN KEY (org_id, route_id) REFERENCES alert_routes (org_id, id) ON DELETE CASCADE
);

-- The composite foreign key is what keeps a route from pointing at
-- another organization's channel: notification_channels already carries
-- UNIQUE (org_id, id) for exactly this.
CREATE TABLE alert_route_channels (
  org_id     uuid NOT NULL,
  route_id   uuid NOT NULL,
  channel_id uuid NOT NULL,
  PRIMARY KEY (route_id, channel_id),
  FOREIGN KEY (org_id, route_id) REFERENCES alert_routes (org_id, id) ON DELETE CASCADE,
  FOREIGN KEY (org_id, channel_id) REFERENCES notification_channels (org_id, id) ON DELETE CASCADE
);

CREATE INDEX alert_route_channels_channel_idx ON alert_route_channels (org_id, channel_id);

-- The ledger, and the reason there is no cursor. alert_events.id is a
-- gen_random_uuid() and therefore not monotonic, and a watermark over
-- `at` would lose an event whose transaction took its timestamp early
-- and committed late. One row per decided event instead: the forward
-- pass is an anti-join against this table, so ordering and overtaking
-- both stop mattering and the primary key IS the idempotency.
--
-- 'expired' is terminal: an event that was suppressed and whose alert
-- closed before the suppression lapsed can never be caught up, because
-- the catch-up pass requires an open alert. Without it such a row would
-- sit in that pass's working set forever.
CREATE TABLE alert_notify_state (
  org_id         uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  alert_event_id uuid PRIMARY KEY REFERENCES alert_events(id) ON DELETE CASCADE,
  state          text NOT NULL CHECK (state IN ('sent', 'suppressed', 'unrouted', 'expired')),
  decided_at     timestamptz NOT NULL
);

-- The catch-up pass reads only suppressed rows; a partial index keeps it
-- cheap as the ledger grows with history.
CREATE INDEX alert_notify_state_pending_idx
  ON alert_notify_state (org_id) WHERE state = 'suppressed';

ALTER TABLE alert_routes ENABLE ROW LEVEL SECURITY;
ALTER TABLE alert_route_severities ENABLE ROW LEVEL SECURITY;
ALTER TABLE alert_route_events ENABLE ROW LEVEL SECURITY;
ALTER TABLE alert_route_channels ENABLE ROW LEVEL SECURITY;
ALTER TABLE alert_notify_state ENABLE ROW LEVEL SECURITY;

-- +goose StatementBegin
DO $$
DECLARE t text;
BEGIN
  FOREACH t IN ARRAY ARRAY['alert_routes', 'alert_route_severities', 'alert_route_events',
                           'alert_route_channels', 'alert_notify_state']
  LOOP
    EXECUTE format('CREATE POLICY org_isolation ON %I USING (org_id = NULLIF(current_setting(''pulsix.org_id'', true), '''')::uuid)', t);
    EXECUTE format('CREATE POLICY org_isolation_bypass ON %I USING (current_setting(''pulsix.org_id'', true) IS NULL OR current_setting(''pulsix.org_id'', true) = '''')', t);
  END LOOP;
END $$;
-- +goose StatementEnd

-- The delivery table's event_kind enum gains the alert batch. Additive,
-- like every migration here: rows written before this keep meaning what
-- they meant.
ALTER TABLE notification_deliveries
  DROP CONSTRAINT notification_deliveries_event_kind_check;
ALTER TABLE notification_deliveries
  ADD CONSTRAINT notification_deliveries_event_kind_check
  CHECK (event_kind IN ('run.finished', 'schedule.skipped', 'schedule.failed',
                        'digest.weekly', 'test', 'alert.batch'));

-- +goose Down
ALTER TABLE notification_deliveries
  DROP CONSTRAINT notification_deliveries_event_kind_check;
ALTER TABLE notification_deliveries
  ADD CONSTRAINT notification_deliveries_event_kind_check
  CHECK (event_kind IN ('run.finished', 'schedule.skipped', 'schedule.failed',
                        'digest.weekly', 'test'));
DROP TABLE alert_notify_state;
DROP TABLE alert_route_channels;
DROP TABLE alert_route_events;
DROP TABLE alert_route_severities;
DROP TABLE alert_routes;
```

```go
// EventKind is one row of alert_events.kind. The seven constants below
// are exactly the CHECK list migration 00049 declares, and
// EventKindsMatchTheSchema pins them to it: a Go copy of a database enum
// with no compiler link between them is how internal/api's fleetStateRank
// drifted from rules.StateRank, which that function's own doc comment
// records. internal/alertroutes needs these names; the type lives here,
// with the table it describes.
type EventKind string

const (
	EventOpened         EventKind = "opened"
	EventSeverityRaised EventKind = "severity_raised"
	EventAcknowledged   EventKind = "acknowledged"
	EventAckVoided      EventKind = "ack_voided"
	EventSnoozed        EventKind = "snoozed"
	EventUnsnoozed      EventKind = "unsnoozed"
	EventClosed         EventKind = "closed"
)

// EventKinds lists every kind, in the schema's own order.
func EventKinds() []EventKind {
	return []EventKind{
		EventOpened, EventSeverityRaised, EventAcknowledged,
		EventAckVoided, EventSnoozed, EventUnsnoozed, EventClosed,
	}
}

// ParseEventKind accepts exactly the seven kind names.
func ParseEventKind(s string) (EventKind, bool) {
	for _, k := range EventKinds() {
		if string(k) == s {
			return k, true
		}
	}
	return "", false
}
```

```go
// Package alertroutes is the bridge between monitoring and delivery
// (spec docs/superpowers/specs/2026-10-12-v0.4b-alert-routes-design.md).
// It owns which alert reaches which notification channel, and nothing
// else: alerts stay with internal/alerts and delivery stays with
// internal/notify, and neither of those two depends on this package.
package alertroutes

// Scope is what a route points at. Routes ADD UP rather than override —
// backlog 4.1b — so a host can be covered by routes at all three levels
// at once and hears from every one of them.
type Scope string

const (
	ScopeOrg             Scope = "org"
	ScopeMonitoringGroup Scope = "monitoring_group"
	ScopeHost            Scope = "host"
)

// Sentinels the API maps to HTTP.
var (
	ErrInvalidInput     = errors.New("invalid input")
	ErrNotFound         = errors.New("not found")
	ErrNameTaken        = errors.New("name already in use")

type Input struct {
	Name       string
	Enabled    bool
	Scope      Scope
	ScopeID    *uuid.UUID // nil exactly when Scope is ScopeOrg
	Severities []rules.State
	Events     []alerts.EventKind
	Channels   []uuid.UUID

// Route is a stored route with its three selections attached.
type Route struct {
	ID         uuid.UUID
	OrgID      uuid.UUID
	Name       string
	Enabled    bool
	Scope      Scope
	ScopeID    *uuid.UUID
	Severities []rules.State
	Events     []alerts.EventKind
	Channels   []uuid.UUID
	Revision   int64
	CreatedAt  time.Time
	UpdatedAt  time.Time
}

// routableSeverities is the set an alert can actually carry: ok is not
// among them, because an alert exists only while something is wrong.
var routableSeverities = []rules.State{rules.StateWarn, rules.StateCrit, rules.StateUnknown}

// Validate rejects a route that cannot do anything. Each of the three
// selections must be non-empty and free of duplicates: a route with no
// channel tells nobody, and one with no severity or no event kind
// matches nothing — states that would otherwise sit in the list looking
// configured while being silent, which is the trap backlog 4.29 records.
func Validate(in Input) error {
	if strings.TrimSpace(in.Name) == "" {
		return fmt.Errorf("%w: a route needs a name", ErrInvalidInput)
	}
	switch in.Scope {
	case ScopeOrg, ScopeMonitoringGroup, ScopeHost:
	default:
		return fmt.Errorf("%w: unknown scope %q", ErrInvalidInput, in.Scope)
	}
	if (in.Scope == ScopeOrg) != (in.ScopeID == nil) {
		return fmt.Errorf("%w: scope %q and its target disagree", ErrInvalidInput, in.Scope)
	}
	if err := checkSet("severity", in.Severities, func(s rules.State) bool {
		return slices.Contains(routableSeverities, s)
	}); err != nil {
		return err
	}
	if err := checkSet("event kind", in.Events, func(k alerts.EventKind) bool {
		_, ok := alerts.ParseEventKind(string(k))
		return ok
	}); err != nil {
		return err
	}
	return checkSet("channel", in.Channels, func(uuid.UUID) bool { return true })
}

// checkSet enforces non-empty, no duplicates and every member known.
func checkSet[T comparable](what string, got []T, known func(T) bool) error {
	if len(got) == 0 {
		return fmt.Errorf("%w: a route needs at least one %s", ErrInvalidInput, what)
	}
	seen := make(map[T]struct{}, len(got))
	for _, v := range got {
		if !known(v) {
			return fmt.Errorf("%w: unknown %s %v", ErrInvalidInput, what, v)
		}
		if _, dup := seen[v]; dup {
			return fmt.Errorf("%w: %s %v listed twice", ErrInvalidInput, what, v)
		}
		seen[v] = struct{}{}
	}
	return nil
}
```
