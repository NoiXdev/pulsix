## Rulings (controller's calls)
- Host list filter: `GET /orgs/{org}/hosts?id=<uuid>&id=<uuid>…` (repeatable, at most 500 ids, the dry run's host cap; more → 422), org-scoped like the list, combinable with the existing filters, permission unchanged. Unknown or foreign ids are simply absent. Group members: if a route already lists members of several groups, use it; otherwise the SPA reads the hosts of all chosen subgroups with one host-list call if the host list can filter by group (check), else keep the pool and say so.
- Sync watcher: lives in `web/src/features/repos/` (or `api/hooks` if it is pure data), state in a small React context or the query cache — no global mutable module state. Poll interval as the run page's job poll (reuse the constant). A job that 404s or errors three times is dropped. The watcher stops when the list is empty. A reload forgets pending syncs (acceptable). The run page's transition hook stays; a completion seen by both invalidates twice, which is harmless.
- `useDeleteHost` invalidates `['host-names', org]`.
- Dry run form: chosen hosts are filtered against the offered hosts for every scope kind that names hosts; for a scope that cannot be listed, keep the choice (the server decides).
- The repository-text 5xx test no longer waits for the real backoff: make the delay injectable (e.g. a module constant the test overrides through a test-only setter in a test kit, or fake timers) — no production behaviour change.
