# Pulsix v0.3b-2 Rules and States Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every value the check pipeline collects gets a meaning — an operator writes rules in a form editor or as an expression, and sees the resulting state per metric, per host and across the fleet, with the deciding rule and its origin always visible.

**Architecture:** Both editor modes compile into one AST stored as `jsonb`. Precedence resolves rules per `(check_key, item, metric, severity)` along `item > host > group > org`. A ticker claims hosts whose data moved or whose deadline came due, evaluates each in a pure function over current values plus window aggregates, and writes states, state changes and a host roll-up in one transaction per host. Nothing notifies anybody: alerting is v0.4.

**Tech Stack:** as v0.3b-1 (Go 1.27, chi v5, huma v2, pgx v5, sqlc, goose, buf, testcontainers-go, React 19, TanStack, Vitest, Playwright, uPlot). **No new dependency in either half.** The expression parser is a hand-written recursive-descent parser: the grammar has ten node kinds, and a third-party expression library would buy roughly 200 lines at the price of a supply-chain entry and a semantics we do not control.

**Spec:** `docs/superpowers/specs/2026-09-29-v0.3b-2-rules-design.md` (binding for every decision below).

## Review Focus

The input classes the spec implies but that no single task's own tests would otherwise exercise. Each already has its pinning test assigned to the task that owns the code; a reviewer checks them deliberately.

1. **Two rules of equal precedence and equal severity.** The same winner on every evaluation, whatever order the candidates are visited in — a resolution that depended on map iteration would make states flap and rewrite history every tick (Task 6).
2. **A window containing no sample, or exactly one.** No value means the rule does not match — never `crit`; `rate` over one sample is not a division by zero (Task 1).
3. **An agent going silent mid-`for_duration`.** `unknown` outranks the ripening candidate, and the candidate is discarded rather than ripening in the dark (Task 8).
4. **A `for_duration` window spanning a manager restart.** `candidate_since` is a row, so the wait survives the process; the state must not restart its clock (Task 8).
5. **Two managers seeing the same host due.** Exactly one evaluation, one set of state changes, no duplicate history rows (Task 9).
6. **An item-scoped rule whose item stops being reported.** The rule survives, the tuple runs into `unknown`, and the effective view says "no longer observed" rather than hiding the rule (Task 6).
7. **A rule deleted while it holds a `crit`.** `ON DELETE SET NULL` keeps the state row; the next tick re-evaluates the tuple and moves it (Task 7).

### Task 1: AST, metric catalogue, node evaluation

**Files:** create `internal/rules/ast.go`, `internal/rules/catalog.go`, `internal/rules/eval_node.go`, `internal/rules/ast_test.go`, `internal/rules/eval_node_test.go`.

**Interfaces — Produces:**
```go
type Kind string

const (
    KindMetric  Kind = "metric"
    KindWindow  Kind = "window"
    KindFact    Kind = "fact"
    KindNumber  Kind = "number"
    KindString  Kind = "string"
    KindArith   Kind = "arith"
    KindCompare Kind = "compare"
    KindLabel   Kind = "label"
    KindAnd     Kind = "and"
    KindOr      Kind = "or"
    KindNot     Kind = "not"
)

// Node is one node of a rule tree. One struct rather than an interface per
// kind: the tree is stored as jsonb and read back by a switch, and a single
// shape keeps encoding, decoding and equality trivial.
type Node struct {
    Kind    Kind     `json:"kind"`
    Name    string   `json:"name,omitempty"`     // metric, window and fact names
    Agg     string   `json:"agg,omitempty"`      // avg | min | max | rate
    Seconds int      `json:"window_s,omitempty"` // window length
    Op      string   `json:"op,omitempty"`
    Num     float64  `json:"num,omitempty"`
    Str     string   `json:"str,omitempty"`
    Values  []string `json:"values,omitempty"`   // label … in (…)
    Args    []Node   `json:"args,omitempty"`
    Pos     int      `json:"-"`                  // source offset, parser only
}

// Input is everything one item's evaluation may read: the current values of
// every metric of that (check_key, item), the window aggregates asked for,
// and the host's facts.
type Input struct {
    Metrics map[string]float64
    Labels  map[string]string
    Windows map[WindowKey]float64
    Facts   map[string]string
}

type WindowKey struct {
    Metric  string
    Agg     string
    Seconds int
}

// Match reports whether n holds for in. A tree that cannot be evaluated does
// not match: missing metric, absent or non-numeric fact, empty window,
// division by zero. Match never returns an error and never escalates.
func Match(n Node, in Input) bool

// Number evaluates a numeric sub-tree. ok is false when any leaf is missing.
func Number(n Node, in Input) (v float64, ok bool)

// WindowKeys lists the window aggregates n needs, deduplicated.
func WindowKeys(n Node) []WindowKey

// MetricKind reports what a metric name carries.
type MetricKind int

const (
    MetricUnknown MetricKind = iota
    MetricNumeric
    MetricDiscrete
)

// Catalogue is the set of metric names the shipped plugins report, with the
// check key each belongs to. It is a table in code for the same reason the
// plugin list in internal/checks is: an unknown metric must be refused when
// the rule is written, not silently never match.
func Catalogue() map[string]CatalogueEntry

type CatalogueEntry struct {
    CheckKey string
    Kind     MetricKind
}

const (
    MinWindow = time.Minute
    MaxWindow = 24 * time.Hour
)

// TypeCheck validates a tree for storage: known metrics, matching kinds,
// window bounds, a boolean root. Errors carry the offending node's Pos.
func TypeCheck(n Node) error

var ErrInvalidRule = errors.New("invalid rule")
```

The catalogue's entries are exactly the metrics v0.3b-1's four plugins emit, read off `internal/agent/checks`: `cpu.used_pct` (numeric, key `cpu`), `mem.used_pct`, `mem.available_bytes`, `swap.used_pct` (numeric, key `memory`), `disk.used_pct`, `disk.free_bytes`, `disk.inodes_used_pct` (numeric, key `disk`), `service.state` (discrete, key `service`). A comment states the obligation: a new plugin metric is added here in the same change that adds the plugin, or no rule can ever name it.

`rate` is `(last − first) / seconds` over the window; the store supplies it pre-computed as a single number per `WindowKey`, so `Match` needs no history of its own.

**Tests:** a table over every node kind — each comparison operator, `and`/`or`/`not` including short-circuit behaviour, arithmetic precedence inside `arith` trees, label `==`/`!=`/`in`. A second table over every non-match path: metric absent from `Input`, fact absent, fact present but not numeric, window key absent, window present with a `rate` of exactly zero over one sample (**review focus 2**), division by zero, a numeric operator applied to a discrete metric. `TypeCheck`: unknown metric, numeric operator on `service.state`, window below `MinWindow`, window above `MaxWindow`, a non-boolean root — each asserting the reported `Pos`. Round-trip `Node` through `encoding/json` and assert the decoded tree equals the original.

Commit: `feat(rules): the rule AST, its metric catalogue and node evaluation`.

### Task 2: Expression parser with positions

**Files:** create `internal/rules/parse.go`, `internal/rules/parse_test.go`.

**Interfaces — Consumes:** `Node`, `Kind`, `TypeCheck`, `ErrInvalidRule` (Task 1).
**Interfaces — Produces:**
```go
// Parse turns expression source into a type-checked tree.
func Parse(src string) (Node, error)

// ParseError is what Parse returns for malformed input: a byte offset into
// src and a message an editor can put under the caret.
type ParseError struct {
    Pos int
    Msg string
}

func (e *ParseError) Error() string
func (e *ParseError) Unwrap() error // ErrInvalidRule
```

Grammar (recursive descent, one function per level):

```
expr       := or
or         := and ("or" and)*
and        := unary ("and" unary)*
unary      := "not" unary | "(" expr ")" | predicate
predicate  := label | comparison
label      := ident ("==" | "!=") string | ident "in" "(" string ("," string)* ")"
comparison := arith ("<" | "<=" | ">" | ">=" | "==" | "!=") arith
arith      := term (("+" | "-") term)*
term       := factor (("*" | "/") factor)*
factor     := number | ident | call | "-" factor | "(" arith ")"
call       := ("avg" | "min" | "max" | "rate") "(" ident "," duration ")"
            | "fact" "(" string ")"
ident      := [a-z][a-z0-9_.]*        -- metric names carry dots
duration   := [0-9]+ ("s" | "m" | "h")
```

A bare `ident` in a numeric position is a `metric` node. `Parse` runs `TypeCheck` before returning, so a parse that succeeds yields a tree the evaluator can always walk.

**Tests:** a table of expressions and their expected trees, covering the spec's own examples — `avg(cpu.used_pct, 10m) > fact("cpu_count") * 0.8`, `disk.used_pct >= 90 or disk.inodes_used_pct >= 90`, `service.state in ("failed", "inactive")`, `not (mem.used_pct < 50)` — plus operator precedence (`a > 1 or b > 2 and c > 3` binds `and` tighter), parenthesised overrides, and unary minus. An error table asserting both message and `Pos`: unterminated string, unknown function, missing comma in a call, trailing operator, empty input, a duration without a unit, a duration with an unknown unit, unbalanced parentheses, and an unknown metric name (surfacing `TypeCheck`'s position through `Parse`). Fuzz-free but property-flavoured: every expression in the success table round-trips through `Format(Parse(src))` to a tree equal to the original (a `Format(Node) string` helper lives here and is what `Rule.Source` is regenerated from when a form rule is converted).

Commit: `feat(rules): a recursive-descent parser for rule expressions`.

### Task 3: Form mode, both directions

**Files:** create `internal/rules/form.go`, `internal/rules/form_test.go`.

**Interfaces — Consumes:** `Node`, `Catalogue`, `MetricKind`, `Format` (Tasks 1–2).
**Interfaces — Produces:**
```go
// Form is the editor's shape: one comparison against a literal, plus an
// optional clear condition for hysteresis.
type Form struct {
    Metric     string
    Op         string   // numeric: > >= < <= == != ; discrete: == != in
    Value      float64  // numeric metrics
    Labels     []string // discrete metrics
    ClearOp    string   // "" when the rule has no clear condition
    ClearValue float64
}

// Compile turns a Form into its trigger tree and its clear tree. The clear
// tree is the zero Node when ClearOp is empty.
func (f Form) Compile() (trigger, clear Node, err error)

// AsForm recovers the Form of a tree pair, reporting false when the trees
// are outside the form subset — which is what makes the editor's one-way
// switch to expression mode visible rather than lossy.
func AsForm(trigger, clear Node) (Form, bool)
```

**Tests:** a round-trip table — every numeric operator, every discrete operator, with and without a clear condition — asserting `AsForm(Compile(f)) == f`. Rejection table for `Compile`: an operator that does not fit the metric's kind, `in` with an empty list, a clear condition on a discrete metric (meaningless: a label does not straddle a threshold), a metric outside the catalogue. Recognition table for `AsForm` returning false: an `or` at the root, a window node, a fact node, an arithmetic node, a comparison of two metrics.

Commit: `feat(rules): the form editor's subset of the AST, both directions`.

### Task 6: Precedence resolution and the effective view

**Files:** create `internal/rules/resolve.go`, `internal/rules/resolve_test.go`; modify `internal/checks/groups.go` (export `GroupsForHost`), `internal/checks/groups_test.go`.

**Interfaces — Consumes:** `Rule`, `Scope`, `Severity` (Task 4).
**Interfaces — Produces:**
```go
// Tuple is what a state is about: one metric of one item of one check on
// one host.
type Tuple struct {
    CheckKey string
    Item     string
    Metric   string
}

// GroupRank is a monitoring group reduced to what the tie-break needs.
type GroupRank struct {
    ID        uuid.UUID
    Priority  int
    CreatedAt time.Time
}

// beats is a strict total order — priority, then the older group, then the
// smaller id, byte for byte. No two distinct groups compare equal, so a
// maximum under it never depends on iteration order.
func (g GroupRank) beats(other GroupRank) bool

type HostContext struct {
    HostID uuid.UUID
    Groups []GroupRank // the groups whose selector matches this host
    Tuples []Tuple     // what the host actually reports today
}

// Effective is the outcome for one (tuple, severity): who decided it and
// who was overruled.
type Effective struct {
    Tuple    Tuple
    Severity Severity
    Winner   Rule
    Shadowed []Rule
    // Observed is false when an item-scoped rule names an item the host no
    // longer reports. The rule still appears, labelled, rather than
    // vanishing from the view.
    Observed bool
}

// Resolve picks a winner per (tuple, severity) along item > host > group >
// org. Disabled rules are dropped before precedence, so disabling a
// host-scoped rule lets the group's rule win rather than leaving the metric
// unjudged. Shadowed holds the losers in the same order Resolve considered
// them, nearest scope first.
func Resolve(rules []Rule, host HostContext) []Effective
```

`internal/checks` gains `func (s *Service) GroupsForHost(ctx context.Context, orgID, hostID uuid.UUID) ([]Group, error)`, built from the same `loadResolveBundle` the check resolver uses, so membership has exactly one implementation in the product. `internal/rules` never imports `internal/checks`: `internal/app` adapts `[]checks.Group` into `[]rules.GroupRank`.

An item-scoped rule for an item that is not in `host.Tuples` still produces an `Effective` with `Observed: false` and the tuple it names — **review focus 6**.

**Tests:** a table mirroring `internal/checks/resolver_test.go`'s shape. Per scope: org only; group over org; host over group; item over host. Among groups: higher priority wins; equal priority, older wins; equal priority and equal `created_at`, smaller id wins (**review focus 1**, asserted by resolving the same input a hundred times from a shuffled slice and requiring one identical result). Severities resolve independently (a host-scoped `warn` and an org-scoped `crit` both survive). Disabled rules do not shadow. An item-scoped rule for a vanished item yields `Observed: false`. A rule whose metric no tuple reports yields no `Effective` at all. `GroupsForHost` gets its own test: a host in two groups, a host in none, and cross-org isolation.

Commit: `feat(rules): precedence resolution with the shadowed rules visible`.

### Task 8: The evaluation function

**Files:** create `internal/rules/evaluate.go`, `internal/rules/evaluate_test.go`.

**Interfaces — Consumes:** everything from Tasks 1, 6 and 7.
**Interfaces — Produces:**
```go
// ItemKey groups the metrics that share an item, because a rule may compare
// siblings: disk.free_bytes and disk.used_pct of the same mount.
type ItemKey struct {
    CheckKey string
    Item     string
}

type TupleSnapshot struct {
    Tuple    Tuple
    Value    *float64
    Label    *string
    Err      string        // collection error reported by the agent
    At       time.Time     // when the agent measured it
    Interval time.Duration // the check's resolved interval
}

type WindowRequest struct {
    Key     ItemKey
    Metric  string
    Agg     string
    Seconds int
}

type Snapshot struct {
    Now       time.Time
    Tuples    []TupleSnapshot
    Effective []Effective
    Windows   map[WindowRequest]float64
    Facts     map[string]string
    Previous  map[Tuple]TupleState
    Changes30 map[Tuple]int
}

type Result struct {
    States  []TupleState
    Changes []Change
    Host    HostState
    NextDue time.Time
}

// WindowRequests is what the store must fetch before Evaluate can run. It
// reads only Tuples and Effective, so the ticker calls it on a Snapshot
// whose Windows field is still nil and fills that field from the result.
func WindowRequests(s Snapshot) []WindowRequest

// Evaluate decides every tuple's state. Pure: no IO, no clock of its own.
func Evaluate(s Snapshot) Result
```

The order of decision, implemented exactly as the spec's "Order of decision, per tuple" lists it:

1. `Err != ""`, or `Now.Sub(At) > 3 × Interval` → `StateUnknown`, and any ripening candidate is discarded (**review focus 3**).
2. Otherwise every `Effective` for the tuple is matched, highest severity first; the first match decides, no match is `StateOK`.
3. Hysteresis: if the previous state is `warn`/`crit` and the deciding rule has a non-zero `Clear`, the state holds until `Match(rule.Clear, …)` is true.
4. `for_duration` downward only: a worse target becomes `Candidate`/`CandidateSince` and takes effect at `CandidateSince + rule.For`; a better target takes effect at once and clears the candidate. A candidate that flips away before ripening is discarded and **writes no `Change`** — the history records states, not intentions.
5. `NextDue` is the earliest of every ripening moment and every staleness deadline (`At + 3 × Interval`), or `Now + 15 s` when there is nothing pending, so a quiet host still gets a cheap heartbeat.
6. Flapping from `Changes30`: set at ≥ 5, cleared at < 3, otherwise carried over from `Previous`.
7. Roll-up via `Worse` with the counts; `Host.Since` carries over while the host state is unchanged.

`Evaluate` builds one `Input` per `ItemKey` from `Tuples` — that is how a rule on `disk.used_pct` reads `disk.free_bytes` of the same mount — and looks window values up by translating each `WindowKey` of the tree into the `WindowRequest` of the tuple's own item.

**Tests:** a large table, one case per row, each fully specified as a `Snapshot` and its expected `Result`. It must contain at least: a threshold crossed with `For: 0` (immediate `crit`); a threshold crossed with `For: 10m` and a `Now` before ripening (state unchanged, candidate set, `NextDue` at the ripening moment); the same at exactly the ripening moment (state changes, one `Change`); a candidate that recovers before ripening (no `Change` written at all); a recovery from `crit` (immediate, no waiting); hysteresis holding a `crit` while the trigger is already false and releasing it when the clear predicate turns true; a stale tuple going `unknown` (`At` older than 3 × interval); a tuple with an `Err` going `unknown` while its value is still fresh; an agent going silent mid-candidate (**review focus 3**: `unknown`, candidate discarded); a `Previous` carrying `CandidateSince` from before a restart, ripening on the first tick after it (**review focus 4**); flapping set at five changes, held at four, cleared at two; the roll-up over one `crit`, one `unknown` and three `ok` yielding `crit` with the right counts; a host whose only tuples are `unknown` rolling up to `unknown`; an empty `Tuples` slice yielding no `HostState` write.

Commit: `feat(rules): the state machine over one host's values`.

```go
type Due struct {
    OrgID, HostID uuid.UUID
}

// HostLoad is everything one host's evaluation reads, gathered before the
// pure function runs.
type HostLoad struct {
    Tuples    []TupleSnapshot
    Effective []Effective
    Facts     map[string]string
    Previous  map[Tuple]TupleState
    Changes30 map[Tuple]int
}

type EvalStore interface {
    // ProcessDue claims up to limit cursors that are dirty or due and runs
    // fn for each inside its own transaction, holding that cursor's row
    // lock. fn's error rolls that host back and leaves its cursor
    // untouched; the other hosts are unaffected.
    ProcessDue(ctx context.Context, now time.Time, limit int, fn func(ctx context.Context, d Due) error) (int, error)
    Load(ctx context.Context, d Due) (HostLoad, error)
    Windows(ctx context.Context, d Due, reqs []WindowRequest, now time.Time) (map[WindowRequest]float64, error)
    Apply(ctx context.Context, d Due, res Result) error
}

func NewTicker(store EvalStore, opts ...TickerOption) *Ticker
func WithTickerClock(now func() time.Time) TickerOption
func WithInterval(d time.Duration) TickerOption // default 15 s
func WithBatch(n int) TickerOption              // default 200

// Tick processes one batch and reports how many hosts it evaluated.
func (t *Ticker) Tick(ctx context.Context) (int, error)

// Run ticks until ctx ends.
func (t *Ticker) Run(ctx context.Context) error
```

The cursor table and its `(next_due_at)` index per the spec. The claim is the spec's statement verbatim, with `FOR UPDATE SKIP LOCKED`; `Apply` writes states, changes, roll-up and the cursor's `evaluated_at`/`next_due_at` in the transaction `ProcessDue` opened (**review focus 5**).

The ingest mark goes into `internal/checks`' existing ingest transaction as one more generated query — the tables are one schema, and a cursor that is written after the commit could be lost. `internal/checks` does not import `internal/rules`; it calls the generated `MarkHostDirty` from `internal/db/gen`, and `samples.go`'s doc comment gains one sentence naming why the statement is there and who reads it.

The window statement is one round trip per host: a `VALUES` list of `(check_key, item, metric, agg, from)` joined laterally against `check_samples`, `avg`/`min`/`max` as aggregates and `rate` as `(last_value − first_value) / seconds` computed from `first_value`/`last_value` window functions. A request whose window holds no row simply returns no entry, which is what makes review focus 2's non-match reach the evaluator.

Tick discipline: an overrun is counted on a `tick_overruns` counter and logged once per occurrence with the batch size and the elapsed time; `Tick` returns after its batch instead of looping, and `Run` waits for the next interval regardless (backlog 2.60's lesson). `now` comes from the injected clock for the pure function, but `ProcessDue`'s comparisons use the database's `now()` (backlog 2.80's lesson).

**Tests:** unit tests for `Ticker` against a fake `EvalStore` — a batch of three hosts, one of which fails (the other two still commit); the overrun counter; `Run` honouring `ctx` cancellation promptly. Integration tests against the real database: two tickers started concurrently against one due host evaluate it exactly once and write exactly one set of changes (**review focus 5**); the window statement over a seeded hypertable for each aggregate, including a window with no rows and a window with exactly one row (`rate` = 0, no division by zero — **review focus 2**); `MarkHostDirty` making a host due; a host whose `next_due_at` has passed being claimed with no new samples at all; `Apply` leaving nothing behind when the transaction rolls back.
