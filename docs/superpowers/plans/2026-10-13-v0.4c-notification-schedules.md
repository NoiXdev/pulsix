# v0.4c Notification Schedules and On-Call Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a notification route a delivery window and an on-call rotation, so that alerts reach whoever is awake and able to act.

**Architecture:** A new package `internal/oncall` holds the rotation — an ordered channel list, a period, an anchor, and a pure `ChannelAt` that answers who is on call at any instant. `internal/alertroutes` gains a delivery window on the route, stored in `maintenance.Window`'s own cron-plus-duration shape so `maintenance.ActiveAt` applies unchanged, plus a breakthrough severity set. The follower gains one more gate between its suppression check and its ledger write, and a fifth ledger state for what that gate holds.

**Tech Stack:** Go 1.27.1 (pinned), pgx v5, sqlc, goose, huma v2, chi v5, React 19, TanStack Query/Router, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-13-v0.4c-notification-schedules-design.md`

## Review Focus

Five things the spec implies that no happy-path test would exercise. Each line's test is written into the task that owns the code.

1. **A rotation whose anchor lies in the future.** `ChannelAt` at an instant before the first handover yields a negative elapsed-period count, and Go's `%` keeps the sign — the naive index is negative and the slice access panics. A rotation created today for a cycle starting Monday is the ordinary case, not an exotic one. → Task 3.
2. **A handover that falls in an hour the clock skips.** On a spring-forward day, 02:30 local does not exist; Go normalizes it forward, which silently moves that one handover. → Task 3.
3. **A breakthrough severity the route does not otherwise fire on.** A route firing only on `crit` with `warn` in its breakthrough set describes a severity that crosses the window but is never routed — meaningless, and it reads as a configuration that works. → Task 6, validation.
4. **A window whose duration exceeds its own period.** Cron daily with a 48-hour duration makes occurrences overlap; `ActiveAt` must still answer, and the GUI must not be able to produce it. → Task 6, validation.
5. **A zero-length or inverted exception span.** `from == to` matches nothing and reads as an effective stand-in; `from > to` is nonsense the database will happily hold. → Task 2, validation.

-- +goose Up
-- v0.4c (spec docs/superpowers/specs/2026-10-13-v0.4c-notification-
-- schedules-design.md): a route gains a delivery window — when it may
-- deliver — and an on-call rotation that chooses its channel by the
-- clock.
--
-- The rotation stores a cycle, not shifts. period_days plus anchor
-- answers "who is on call" for any instant by arithmetic, so the roster
-- never runs out and needs no generator to refill it (decision 5). The
-- anchor IS the first handover, date and time together: a separate
-- handover-time column would be one fact stored twice, and the first
-- disagreement between them would have no right answer.
CREATE TABLE oncall_rotations (
  id          uuid PRIMARY KEY,
  org_id      uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  name        text NOT NULL,
  period_days integer NOT NULL CHECK (period_days > 0),
  anchor      timestamptz NOT NULL,
  timezone    text NOT NULL,
  revision    bigint NOT NULL DEFAULT 1,
  created_at  timestamptz NOT NULL,
  updated_at  timestamptz NOT NULL,
  UNIQUE (org_id, name),
  UNIQUE (org_id, id)
);

-- position orders the cycle. UNIQUE (rotation_id, position) is what makes
-- "the channel at index i" a single row rather than a guess.
CREATE TABLE oncall_rotation_channels (
  org_id      uuid NOT NULL,
  rotation_id uuid NOT NULL,
  position    integer NOT NULL CHECK (position >= 0),
  channel_id  uuid NOT NULL,
  PRIMARY KEY (rotation_id, position),
  FOREIGN KEY (org_id, rotation_id) REFERENCES oncall_rotations (org_id, id) ON DELETE CASCADE,
  FOREIGN KEY (org_id, channel_id) REFERENCES notification_channels (org_id, id) ON DELETE CASCADE
);

-- A stand-in: for this span, this channel instead of whatever the cycle
-- says. starts_at < ends_at is enforced here rather than left to the
-- application, because a zero-length span reads in the GUI as a working
-- stand-in while matching nothing at all.
CREATE TABLE oncall_exceptions (
  id          uuid PRIMARY KEY,
  org_id      uuid NOT NULL,
  rotation_id uuid NOT NULL,
  starts_at   timestamptz NOT NULL,
  ends_at     timestamptz NOT NULL,
  channel_id  uuid NOT NULL,
  note        text NOT NULL DEFAULT '',
  created_at  timestamptz NOT NULL,
  FOREIGN KEY (org_id, rotation_id) REFERENCES oncall_rotations (org_id, id) ON DELETE CASCADE,
  FOREIGN KEY (org_id, channel_id) REFERENCES notification_channels (org_id, id) ON DELETE CASCADE,
  CONSTRAINT oncall_exceptions_span CHECK (starts_at < ends_at)
);

CREATE INDEX oncall_exceptions_rotation_idx ON oncall_exceptions (org_id, rotation_id, starts_at);

-- The route's delivery window, in maintenance_windows' own shape so that
-- maintenance.ActiveAt applies with no translation layer (decision 2).
-- The three columns are one fact: a cron without a duration is not a
-- window, it is an instant.
ALTER TABLE alert_routes
  ADD COLUMN window_cron             text,
  ADD COLUMN window_duration_seconds integer CHECK (window_duration_seconds > 0),
  ADD COLUMN window_timezone         text,
  ADD COLUMN rotation_id             uuid,
  ADD CONSTRAINT alert_routes_window_complete CHECK (
    (window_cron IS NULL AND window_duration_seconds IS NULL AND window_timezone IS NULL) OR
    (window_cron IS NOT NULL AND window_duration_seconds IS NOT NULL AND window_timezone IS NOT NULL)
  ),
  ADD CONSTRAINT alert_routes_rotation_fkey
    FOREIGN KEY (org_id, rotation_id) REFERENCES oncall_rotations (org_id, id) ON DELETE SET NULL;

-- The fourth selection table: severities that cross a closed window
-- (decision 3). Deliberately a separate table rather than a flag on
-- alert_route_severities, because it is a different question — "does the
-- route fire on this" versus "does it fire even now".
CREATE TABLE alert_route_breakthrough_severities (
  org_id   uuid NOT NULL,
  route_id uuid NOT NULL,
  severity text NOT NULL CHECK (severity IN ('warn', 'crit', 'unknown')),
  PRIMARY KEY (route_id, severity),
  FOREIGN KEY (org_id, route_id) REFERENCES alert_routes (org_id, id) ON DELETE CASCADE
);

-- The fifth ledger state. Holding for a delivery window is structurally
-- what 'suppressed' already does — hold, re-check, send when the alert is
-- still open — but it is a different WHY, and v0.4b's decision 8 made
-- "why did nothing arrive" a queryable fact rather than an absence.
ALTER TABLE alert_notify_state
  DROP CONSTRAINT alert_notify_state_state_check;
ALTER TABLE alert_notify_state
  ADD CONSTRAINT alert_notify_state_state_check
  CHECK (state IN ('sent', 'suppressed', 'unrouted', 'expired', 'deferred'));

-- The catch-up pass now reads two states, so the partial index must cover
-- both or it stops being used.
DROP INDEX alert_notify_state_pending_idx;
CREATE INDEX alert_notify_state_pending_idx
  ON alert_notify_state (org_id) WHERE state IN ('suppressed', 'deferred');

ALTER TABLE oncall_rotations ENABLE ROW LEVEL SECURITY;
ALTER TABLE oncall_rotations FORCE ROW LEVEL SECURITY;
ALTER TABLE oncall_rotation_channels ENABLE ROW LEVEL SECURITY;
ALTER TABLE oncall_rotation_channels FORCE ROW LEVEL SECURITY;
ALTER TABLE oncall_exceptions ENABLE ROW LEVEL SECURITY;
ALTER TABLE oncall_exceptions FORCE ROW LEVEL SECURITY;
ALTER TABLE alert_route_breakthrough_severities ENABLE ROW LEVEL SECURITY;
ALTER TABLE alert_route_breakthrough_severities FORCE ROW LEVEL SECURITY;

-- +goose StatementBegin
DO $$
DECLARE t text;
BEGIN
  FOREACH t IN ARRAY ARRAY['oncall_rotations', 'oncall_rotation_channels',
                           'oncall_exceptions', 'alert_route_breakthrough_severities']
  LOOP
    EXECUTE format('CREATE POLICY org_isolation ON %I USING (org_id = NULLIF(current_setting(''pulsix.org_id'', true), '''')::uuid)', t);
    EXECUTE format('CREATE POLICY org_isolation_bypass ON %I USING (current_setting(''pulsix.org_id'', true) IS NULL OR current_setting(''pulsix.org_id'', true) = '''')', t);
  END LOOP;
END $$;
-- +goose StatementEnd

-- +goose Down
DROP INDEX alert_notify_state_pending_idx;
CREATE INDEX alert_notify_state_pending_idx
  ON alert_notify_state (org_id) WHERE state = 'suppressed';
ALTER TABLE alert_notify_state DROP CONSTRAINT alert_notify_state_state_check;
ALTER TABLE alert_notify_state
  ADD CONSTRAINT alert_notify_state_state_check
  CHECK (state IN ('sent', 'suppressed', 'unrouted', 'expired'));
DROP TABLE alert_route_breakthrough_severities;
ALTER TABLE alert_routes
  DROP CONSTRAINT alert_routes_rotation_fkey,
  DROP CONSTRAINT alert_routes_window_complete,
  DROP COLUMN rotation_id,
  DROP COLUMN window_timezone,
  DROP COLUMN window_duration_seconds,

```go
// Package oncall answers one question: which notification channel is on
// call at a given instant (spec docs/superpowers/specs/2026-10-13-v0.4c-
// notification-schedules-design.md). It stores a cycle rather than
// shifts — an ordered channel list, a period and an anchor — so the
// roster never runs out and needs no generator to refill it, and so the
// answer costs the same for any instant, past or future.
//
// A rotation cycles CHANNELS, not people. Pulsix has no notion of a
// person's own address, and inventing one here would commit the shape a
// later per-user inbox has to live with.
package oncall

// Sentinels the API maps to HTTP.
var (
	ErrInvalidInput     = errors.New("invalid input")
	ErrNotFound         = errors.New("not found")
	ErrNameTaken        = errors.New("name already in use")
	ErrRevisionMismatch = errors.New("revision mismatch")
)

// Input is a rotation as an operator supplies it.
type Input struct {
	Name       string
	PeriodDays int
	// Anchor is the FIRST HANDOVER itself, date and time together, not a
	// date with a separate handover-time beside it: two fields would be
	// one fact stored twice, and their first disagreement would have no
	// right answer.
	Anchor   time.Time
	Timezone string
	Channels []uuid.UUID // ordered; position in this slice is the cycle order
}

// Rotation is a stored rotation with its channel list attached.
type Rotation struct {
	ID, OrgID  uuid.UUID
	Name       string
	PeriodDays int
	Anchor     time.Time
	Timezone   string
	Channels   []uuid.UUID
	Revision   int64
	CreatedAt  time.Time
	UpdatedAt  time.Time
}

// ExceptionInput is a stand-in as an operator supplies it.
type ExceptionInput struct {
	StartsAt, EndsAt time.Time
	ChannelID        uuid.UUID
	Note             string
}

// Exception is a stored stand-in: for this span, this channel instead of
// whatever the cycle says.
type Exception struct {
	ID, OrgID, RotationID, ChannelID uuid.UUID
	StartsAt, EndsAt                 time.Time
	Note                             string
	CreatedAt                        time.Time
}

// Validate rejects a rotation that cannot answer who is on call.
func Validate(in Input) error {
	if strings.TrimSpace(in.Name) == "" {
		return fmt.Errorf("%w: a rotation needs a name", ErrInvalidInput)
	}
	if in.PeriodDays <= 0 {
		return fmt.Errorf("%w: the period must be at least one day, got %d", ErrInvalidInput, in.PeriodDays)
	}
	if in.Anchor.IsZero() {
		return fmt.Errorf("%w: a rotation needs an anchor — the first handover", ErrInvalidInput)
	}
	if _, err := time.LoadLocation(in.Timezone); err != nil {
		return fmt.Errorf("%w: unknown timezone %q", ErrInvalidInput, in.Timezone)
	}
	if len(in.Channels) == 0 {
		return fmt.Errorf("%w: a rotation needs at least one channel", ErrInvalidInput)
	}
	seen := make(map[uuid.UUID]struct{}, len(in.Channels))
	for _, c := range in.Channels {
		if _, dup := seen[c]; dup {
			return fmt.Errorf("%w: channel %v listed twice", ErrInvalidInput, c)
		}
		seen[c] = struct{}{}
	}
	return nil
}

// ValidateException rejects a span that matches no instant. Both a
// zero-length and an inverted span read in the GUI as a working stand-in
// while covering nothing, which is the failure worth refusing at the door.
func ValidateException(in ExceptionInput) error {
	if in.StartsAt.IsZero() || in.EndsAt.IsZero() {
		return fmt.Errorf("%w: a stand-in needs a start and an end", ErrInvalidInput)
	}
	if !in.StartsAt.Before(in.EndsAt) {
		return fmt.Errorf("%w: a stand-in must start before it ends", ErrInvalidInput)
	}
	if in.ChannelID == uuid.Nil {
		return fmt.Errorf("%w: a stand-in needs a channel", ErrInvalidInput)
	}
	return nil
}

// handoverIndex counts how many handovers have happened at or before at,
// relative to the anchor. It may be negative: a rotation created today
// for a cycle anchored next Monday is an ordinary thing to configure, and
// every instant before that anchor sits at a negative index.
//
// The counting is CALENDAR arithmetic, stepping whole days in the
// rotation's own location, and not (at - anchor) / period. Duration
// arithmetic drifts: with a seven-day period and a handover at 09:00
// local, every daylight-saving change moves that handover an hour and the
// error accumulates, until years later the rota hands over at night.
func handoverIndex(r Rotation, at time.Time) (int, error) {
	loc, err := time.LoadLocation(r.Timezone)
	if err != nil {
		return 0, fmt.Errorf("rotation %s: unknown timezone %q: %w", r.ID, r.Timezone, err)
	}
	anchor := r.Anchor.In(loc)
	target := at.In(loc)

	// Step forward or backward a period at a time. The loop is bounded by
	// the distance in days divided by the period, so it is linear in the
	// number of periods rather than in time.
	days := int(target.Sub(anchor).Hours() / 24)
	guess := days / r.PeriodDays
	// AddDate normalizes a date that does not exist locally (02:30 on a
	// spring-forward day), which is the defined behaviour this relies on.
	for anchor.AddDate(0, 0, guess*r.PeriodDays).After(target) {
		guess--
	}
	for !anchor.AddDate(0, 0, (guess+1)*r.PeriodDays).After(target) {
		guess++
	}
	return guess, nil
}

// ChannelAt reports which channel is on call at at: the cycle's answer,
// overridden by the winning stand-in when one covers that instant.
func ChannelAt(r Rotation, exc []Exception, at time.Time) (uuid.UUID, error) {
	if len(r.Channels) == 0 {
		return uuid.Nil, fmt.Errorf("rotation %s has no channels", r.ID)
	}
	if win, ok := winningException(exc, at); ok {
		return win.ChannelID, nil
	}
	idx, err := handoverIndex(r, at)
	if err != nil {
		return uuid.Nil, err
	}
	n := len(r.Channels)
	// Go's % keeps the sign of the dividend, so a negative index would
	// address outside the slice. The second modulo folds it back.
	return r.Channels[((idx%n)+n)%n], nil
}

// winningException picks the stand-in covering at under the strict total
// order of decision 7: later start wins; same start, later end wins; a
// tie goes to the smaller id, byte for byte. Ids are unique, so no two
// distinct exceptions ever compare equal and folding over a slice never
// depends on the order it was visited in.
//
// The span is half-open, [StartsAt, EndsAt): a stand-in that ends at 09:00
// is over at 09:00, which is what lets two consecutive stand-ins meet
// without overlapping.
func winningException(exc []Exception, at time.Time) (Exception, bool) {
	var best Exception
	found := false
	for _, e := range exc {
		if at.Before(e.StartsAt) || !at.Before(e.EndsAt) {
			continue
		}
		if !found || beatsException(e, best) {
			best, found = e, true
		}
	}
	return best, found
}

func beatsException(a, b Exception) bool {
	if !a.StartsAt.Equal(b.StartsAt) {
		return a.StartsAt.After(b.StartsAt)
	}
	if !a.EndsAt.Equal(b.EndsAt) {
		return a.EndsAt.After(b.EndsAt)
	}
	return bytes.Compare(a.ID[:], b.ID[:]) < 0
}
```

// Window is a route's delivery window: when it MAY deliver, not when it
// may not (spec decision 2). It is stored in maintenance.Window's own
// shape — cron for the start instants, a duration to make each an
// interval, and a timezone — so maintenance.ActiveAt applies with no

	Duration time.Duration
	Timezone string

// error messages.
func (w Window) ToMaintenance(id uuid.UUID) maintenance.Window {
