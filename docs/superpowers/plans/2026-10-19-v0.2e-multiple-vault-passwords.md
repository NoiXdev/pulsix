# More than one vault password per play — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playbook run can decrypt vault files encrypted with several different passwords, because a repository and its job template each carry labelled vault credentials.

**Architecture:** Two link tables replace one column. The manager resolves a run's set — the repository's union the template's, template winning a label collision — and hands the worker the answer rather than the rule, through a new repeated proto field. The runner writes one 0600 file per credential and emits `vault_identity_list` instead of `vault_password_file`.

**Tech Stack:** Go 1.27.1, pgx v5, sqlc 1.31.1, goose, huma v2, buf/protobuf, PostgreSQL 18, React 19, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-v0.2e-multiple-vault-passwords-design.md`

## Global Constraints

- Migrations are additive only. `git_repos.vault_credential_id` is backfilled and then left unread; dropping it is a separate backlog row, not this plan's business.
- Every tenant table carries `org_id`, composite foreign keys `(org_id, id)`, and the `org_isolation` / `org_isolation_bypass` policy pair with **both** `ENABLE` and `FORCE ROW LEVEL SECURITY`. Copy the `DO` block from the newest migration rather than writing one.
- Layers, strictly: `internal/api` decodes and calls a service; services hold rules and no SQL; stores are sqlc behind a small interface. Handlers never touch `gen.Queries`.
- The worker receives resolved values, never resolution rules.
- Secrets never reach a log, an error message or a test fixture in plaintext. A vault password file is mode 0600 and lives only inside the job's work directory.
- Run the race suite as `make test`, never a whole-module `go test ./...`. `internal/e2e` gets its own invocation. `golangci-lint run` must pass before every commit.
- Coverage: Go ≥ 80 % overall, ≥ 90 % for auth, tenancy and db; SPA ≥ 70 %.
- `node` is not on PATH: `export PATH="$HOME/.nvm/versions/node/v24.14.0/bin:$PATH"`, run from `web/`.
- Conventional Commits, footer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`. Commit after each task; do not push, do not merge.
- **Read the real helpers before transcribing any test code.** Briefs in this repository have repeatedly named helpers that do not exist. The convention is `d := testdb.Open(t)` with a local `ctx`; database-backed tests in `internal/alertroutes` do **not** use `t.Parallel()` because they share one container.

## Review Focus

Five things the spec implies that a task could ship without noticing, most likely to bite first.

1. **A credential leaking into a run that should not have it.** The union widens what a run can decrypt, and the failure is silent — the run simply succeeds with more power than intended. Pinned in Task 2.
2. **A label collision resolving the wrong way.** The template must win. Resolution order inside a map iteration is undefined in Go, so a naive merge can be correct in testing and wrong in production. Pinned in Task 2.
3. **An old worker meeting a new manager.** The new proto field is invisible to it, so it decrypts nothing — which must fail loudly rather than run a play that silently skips encrypted variables. Pinned in Task 3.
4. **An existing repository with one vault credential.** It must keep working unchanged after the migration, with its password appearing as `default`. Pinned in Task 1.
5. **A vault password reaching a log.** The runner handles plaintext secrets; an error path that includes the file's contents, or a debug line naming the password rather than the label, is the failure nobody notices until an audit. Pinned in Task 3.

## Task 1: Migration 00059 and the backfill

**Files:**

- Test: `internal/db/schema_test.go`

**Interfaces:**
- Produces: `git_repo_vault_credentials` and `job_template_vault_credentials`, both `(org_id, parent_id, credential_id, label)` with `PRIMARY KEY (parent_id, label)`.

- [ ] **Step 1: Write the failing schema tests**

Three cases, in `internal/db/schema_test.go`'s own style — read its existing helpers first and extend rather than invent:

- a label may not repeat under one repository (the primary key), while the same credential may appear twice under different labels;
- a link row may not name another organization's credential (the composite foreign key);
- **Review Focus 4:** a `git_repos` row carrying `vault_credential_id` before the migration has, after it, exactly one link row with label `default` naming that credential.

The third needs the migration applied over seeded data. If `testdb` applies all migrations at once and gives no hook for "seed, then migrate", say so in your report and pin the backfill with a direct `SELECT` against a row the fixtures create instead — do not quietly drop the case.

- [ ] **Step 2: Run them and watch them fail**

```bash
go test -race -timeout 900s ./internal/db/... -run 'Vault'
```

- [ ] **Step 3: Write the migration**

Both tables exactly as the spec's Data section gives them, including the deliberate foreign-key asymmetry: the parent cascades, the credential does not, so deleting a credential still in use is refused.

The backfill is one statement per table — only `git_repos` has a column to read:

```sql
INSERT INTO git_repo_vault_credentials (org_id, repo_id, credential_id, label)
SELECT org_id, id, vault_credential_id, 'default'
FROM git_repos
WHERE vault_credential_id IS NOT NULL;
```

Comment why `default` and not something descriptive: it is Ansible's own default vault id, so a file encrypted without an explicit label keeps matching and behaviour is unchanged.

Then the `DO` block with `ENABLE`, `FORCE` and both policies, copied from `00056_escalation_chains.sql`.

## Task 2: The resolution

**Files:**
- Create: `internal/repos/vault.go`, `internal/repos/vault_test.go`
- Create: `internal/db/queries/vault_identities.sql`
- Modify: `internal/repos/store_sql.go`, `internal/templates/store_sql.go`

**Interfaces:**
- Produces:

```go
// VaultIdentity is one labelled vault password, resolved for a run.
type VaultIdentity struct {
	CredentialID uuid.UUID
	Label        string
	FromTemplate bool // for the run detail: where this one came from
}

// ResolveVaultIdentities merges a repository's identities with its job
// template's. A label present on both resolves to the template's, which
// is the same org → group → host → item precedence internal/rules uses:
// the more specific beats the more general. The result is ordered by
// label so a run's ansible.cfg is byte-stable across ticks.
func ResolveVaultIdentities(repo, template []VaultIdentity) []VaultIdentity
```

- [ ] **Step 1: Write the failing tests**

Table-driven, no database. Cases, each named for what it pins:

- repository only, template only, neither — the identity cases;
- disjoint labels merge, and the result is **sorted by label**;
- **Review Focus 2:** the same label on both sides resolves to the template's credential, and `FromTemplate` is true for it;
- the same label on both sides with the *same* credential yields one entry, not two;
- a repository identity that the template does not touch keeps `FromTemplate` false.

The ordering case matters beyond tidiness: without it the merge is a map iteration, which Go randomises, and `ansible.cfg` would differ between two runs of the same job for no reason.

- [ ] **Step 2: Run and watch them fail**

```bash
go test -race -timeout 900s ./internal/repos/... -run TestResolveVaultIdentities
```

- [ ] **Step 3: Write it** — pure, no clock, no database, the same shape `rules.Resolve` and `alerts.Mute` have.

- [ ] **Step 4: Write the queries and wire both stores.** Replace-a-set is **delete then insert, two statements, never one data-modifying `WITH`** — a CTE's statement order is undefined in Postgres and that exact mistake lost a row in v0.4b. `internal/db/queries/alert_routes.sql` carries the pairs that replaced it.

- [ ] **Step 5: Add the store round-trip test** — **Review Focus 1**: a template's identities must not appear in a sibling template's resolved set on the same repository. Build two templates on one repository, give each its own identity, and assert each run resolves to its own plus the repository's, never the other's.

- [ ] **Step 6: Run and commit**

```bash
go test -race -timeout 900s ./internal/repos/... ./internal/templates/...
make sqlc && golangci-lint run
git add internal/repos internal/templates internal/db
git commit -m "feat(repos): resolve a run's labelled vault identities
```

## Task 3: The worker

**Files:**
- Modify: `proto/pulsix/worker/v1/worker.proto`, `internal/worker/runner/inventory.go`, `internal/worker/runner/layout.go`
- Test: the runner's existing test files

**Interfaces:**
- Consumes: `VaultIdentity` from Task 2.
- Produces: `Job.vault_identities`, a **new** repeated field; field 20 becomes `reserved`.

- [ ] **Step 1: Change the proto**

```proto
  reserved 20;  // was string vault_credential_id, replaced by the repeated
                // field below. Never reuse the number: a worker built
                // against the old descriptor would read the new bytes as a
                // malformed string rather than failing cleanly.
  repeated VaultIdentity vault_identities = 21;
```

21 is the next free number — 20 is the highest in use across the whole file today, and reserving it leaves 21 as the first available. Verify that is still true when you get there rather than trusting this line, then `make buf-generate`.

- [ ] **Step 2: Write the failing runner tests**

- N credentials produce N files, each mode 0600, inside the job's work directory;
- `ansible.cfg` carries `vault_identity_list = label@path, label@path` in label order, and **no** `vault_password_file`;
- no identities produces neither line, as today;
- **Review Focus 5:** a credential the claim names but does not reveal fails with an error naming the **label and the credential id**, never the password. Assert on the error's text, not only that it is non-nil.
- **Review Focus 3:** a job whose `vault_identities` is empty but whose playbook needs a vault fails loudly — the run errors rather than succeeding with variables silently unresolved. This is the old-worker-meets-new-manager shape, and the test stands in for it because an old binary cannot be run here.
