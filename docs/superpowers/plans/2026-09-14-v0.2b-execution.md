# Pulsix v0.2b Execution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The execution half of milestone v0.2: the internal CA with mTLS gRPC between worker and manager, the Postgres job queue with `SKIP LOCKED`, Git repositories, the playbook editor, job templates, live Ansible runs streamed to the SPA, SSH bootstrap, connection test with host-key TOFU and pinning, daily re-tests, and key rotation — ending in the Ansible E2E scenario that is the milestone gate.

**Architecture:** The manager stays the only process that talks SQL. `cmd/worker` is a new Go binary that authenticates with a client certificate issued by `internal/ca`, claims jobs of its zone with `SELECT … FOR UPDATE SKIP LOCKED` over gRPC, runs `ansible-runner` as a subprocess with a private temp dir, and streams events back over a bidirectional gRPC stream; the manager persists `job_events` and fans them out to the SPA over Server-Sent Events. The inventory snapshot a job runs against is rendered by the same `internal/inventory/render` code as the preview, with secrets revealed, and delivered only inside the claim response over TLS 1.3. Connection tests and bootstrap are internal jobs (kinds `connection_test`, `bootstrap`, `rotate_key`) executed by the worker with `golang.org/x/crypto/ssh` and the embedded `pulsix.bootstrap` playbook.

**Tech Stack:** as v0.2a (Go 1.27, chi v5, huma v2, pgx v5, sqlc, goose v3, testcontainers-go, React 19, TanStack Router/Query, Tailwind v4, Vitest, Playwright) plus `google.golang.org/grpc`, `buf.build` protos, `golang.org/x/crypto/ssh`, and the pinned `ansible`/`ansible-runner` in the worker image.

## Decisions taken in this plan

- **Two listeners.** The manager serves HTTP on `PULSIX_LISTEN` as today and gRPC on `PULSIX_GRPC_LISTEN` (default `:8444`, empty disables it). The gRPC server requires client certificates signed by the internal CA; the manager's own serving certificate is the operator's reverse proxy concern (spec §14) and out of scope — for the compose stack the gRPC port is served with a manager-issued self-signed server certificate from the same CA, and workers pin it via the CA pool they were enrolled with.
- **Worker enrollment is a manager CLI command.** `pulsix-manager worker add --zone <slug> --name <name>` (a subcommand of the existing binary, not an HTTP route) prints the client certificate, private key and CA PEM to stdout once. The worker reads `PULSIX_MANAGER_ADDR`, `PULSIX_WORKER_CERT`, `PULSIX_WORKER_KEY`, `PULSIX_CA_CERT` as file paths. The workers row stores the certificate serial; the gRPC interceptor looks the serial up on every call and rejects unknown or revoked serials. A worker can be revoked by deleting its row; `last_seen`, `version` are updated on every claim.
- **The CA is instance-local, stored in the database.** `internal/ca` generates an ECDSA P-384 CA on first start and stores it sealed (master key, AAD `ca:<instance>`) in a new `instance_ca` table — no extra volume, survives manager restarts, backs up with the database. `pulsix-manager worker add` opens the database and the master key to issue. Serial numbers are random 64-bit values (not a counter), collision-safe under the unique index.
- **Job kinds and the queue.** `jobs.kind` is `run` (job template), `adhoc` (2.14), `connection_test`, `bootstrap`, `rotate_key`. All kinds share one queue and one claim path. `jobs.zone_id` selects the claiming worker (a template targeting hosts in several zones is split into one job per zone at enqueue time, all sharing a `run_group_id` so the run view can show them together). Claim is `UPDATE jobs SET status='claimed', worker_id=$w, claimed_at=now() WHERE id = (SELECT id FROM jobs WHERE status='queued' AND zone_id = ANY($zones) ORDER BY created_at FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING …` — one round trip, safe under concurrency (integration-tested with parallel claimers).
- **Snapshot delivery.** The claim response embeds the rendered inventory document (from `Renderer.Snapshot` — same code as the preview, secrets revealed), the `Connections` map, and a `credentials` map holding the revealed secret of every credential a targeted host or bastion references (backlog 2.17's separate secret read). Hosts whose pinned host key mismatches their stored fingerprint are **not** rendered into the snapshot; if that empties the scope the claim fails the job with a per-job error instead of running against a partial inventory.
- **Event streaming.** After claiming, the worker opens `RunEvents` (bidirectional stream, job id in the metadata). Worker → manager: event messages (`seq`, `host`, `task`, `state`, `payload jsonb`, `stdout line`). Manager → worker: at most one `cancel` message. The manager appends every event to `job_events` (TimescaleDB hypertable, compressed after 7 days), updates `jobs.status`/`stats`, and pushes to SSE subscribers. Terminal states are `succeeded`, `failed`, `cancelled`, `error` (worker/infrastructure failure). A claimed job with no stream open within 30 s, or a stream that dies mid-run, is set back to `queued` by the manager's reaper (at-least-once; ansible is idempotent-friendly, and the run view shows the restart).
- **Connection test is Go, not ansible.** The worker dials with `golang.org/x/crypto/ssh` through the resolved jump chain: TCP reachability, host key fingerprint (SHA256, base64, the OpenSSH format), auth with the host's credential, `sudo -n true` for passwordless sudo, `python3 -c 'print(1)'` for Python. Result is one row in `host_connection_tests` with a `checks` jsonb (per-check ok/detail). TOFU: the first test for a host reports `host_key_state: "unpinned"`; the operator pins via the API (spec: fingerprint shown for manual comparison — the UI shows it and asks for confirmation). A later test whose fingerprint differs from the pin is `host_key_changed`, the host's stored test state goes critical, and the claim-time check blocks jobs for that host (decision above).
- **Daily re-test.** The manager's scheduler goroutine (advisory-locked, one holder like the v0.1 scheduler pattern) enqueues one `connection_test` per managed host per day, staggered by `hash(host_id) % 24h`, skipping hosts that already have a queued test. Also re-runs after every credential rotation (the rotation job itself ends with a test).
- **Bootstrap.** `POST /hosts/{id}/bootstrap` takes an existing login (user + password or private key) **used once and never stored**; the manager enqueues a `bootstrap` job whose payload carries that login plus the public key of the host's SSH credential. The worker materializes the embedded `pulsix.bootstrap` playbook (creates/updates the `ansible` user, installs the public key, passwordless sudo rule) and runs it with ansible-runner. The response is the job id; the UI polls the run view. If the host has no SSH credential of kind `ssh_key`, bootstrap is rejected 422.
- **Key rotation.** `POST /credentials/{id}/rotate` on a `ssh_key` credential: the manager generates the new keypair in memory (the credential service's existing generator), enqueues one `rotate_key` job per host (and bastion) that references the credential — the payload carries old and new private keys, the worker installs the new public key through the old key (a 6-line embedded playbook) and ends with a connection test using the new key; when every job of the rotation group succeeds the manager seals the new private key into the credential (single transaction), otherwise the credential keeps the old key and the run view shows which hosts failed. Rotating a credential that is referenced by nothing simply re-keys it immediately.
- **Git repos.** `git_repos(org_id, name, url, credential_id (git_key|git_token), branch, subpath, last_sync, last_sync_error)`; sync happens on the worker before every run (`git clone`/`git fetch` + `git reset` into a per-repo cache under the worker's data dir, then `ansible-galaxy install -r requirements.yml` when the file exists) and on demand via `POST /repos/{id}/sync`, which enqueues a `sync_repo` job (sixth job kind) so the manager never shells out. Sync errors surface as `last_sync_error` and a warning on runs.
- **Playbooks.** `playbooks(org_id, repo_id NULL, path NULL, inline NULL, source repo|editor)`; exactly one of path/inline per source (CHECK constraint). The editor playbook is validated at save time: it must parse as YAML and be a list whose first element is a mapping with a `hosts` key (the same check `ansible-playbook --syntax-check` would approximate; a full syntax check happens on the worker before a run and fails the job early).
- **Job templates.** `job_templates(org_id, name, playbook_id, scope jsonb (render.Scope wire format: group_id/host_ids/null), limit text, extra_vars jsonb, extra_vars_schema jsonb NULL, credential_id NULL)`. Extra vars are validated against the optional schema with the same `internal/inventory/schema` package groups use (schema §7 "typed by an optional schema like groups"). The credential on the template is the *default* SSH credential for hosts that have none of their own. Zone selection is derived from the targeted hosts (spec §7), not stored.
- **Ad-hoc command (2.14).** `POST /hosts/command` with host ids, module (`shell` only in v0.2b), and argv — enqueued as an `adhoc` job; the worker builds a one-task inline playbook (`ansible.builtin.shell`/module call with the argv). Output streams like any run. `jobs.run` permission (operator) gates it.
- **Permissions.** New entries in the fixed matrix: `repos.read` (viewer), `repos.write` (operator), `playbooks.read` (viewer), `playbooks.write` (operator), `jobs.read` (viewer), `jobs.run` (operator), `workers.write` (admin). Connection test and bootstrap are `inventory.write` (they act on host access); rotate is `credentials.write`.
- **Audit objects.** New object types: `git_repo`, `playbook`, `job_template`, `job`, `worker`, `host_connection_test`, `credential_rotation`. Claims and event appends are recorded as `job.claim`/`job.event` audit events by the gRPC layer (system actor, no user).
- **2.22 decision (from the v0.2a review).** A stray sealed value outside the job's scope keeps failing a scoped snapshot (fail closed) — no change to `Renderer.Snapshot`; the error message gains the container-type context the review asked for (Task 18 covers 2.15–2.22; 2.22's message part is folded into it).
- **Worker image.** `deploy/worker/Dockerfile` builds the Go worker binary on top of `ghcr.io/ansible-community/ansible-runner` (newest tag pinned) and installs `ansible-core` via the image's pip; the compose `worker` service uses it. The compose default also runs an embedded worker in the manager container (`PULSIX_EMBEDDED_WORKER=1`): the same worker package, started in-process, so `docker compose up` works with zero extra services. The embedded worker authenticates through a loopback-issued certificate at startup.
- **Protos live in `proto/`, built with buf.** `buf.yaml`, `buf.gen.yaml`, `buf lint` and `buf breaking` (against the previous commit) run in CI. Generated Go goes to `internal/pb/` (checked in, like sqlc output).

### Task 1: The internal CA

Spec §14: agents and workers authenticate with client certificates from the manager's internal CA. This task is the pure math plus its sealed storage, fully unit- and integration-tested, with no gRPC yet.

**Files:**
- Create: `internal/ca/ca.go`
- Create: `internal/ca/store_sql.go`

- Test: `internal/ca/ca_test.go`, `store_sql_test.go`

**Interfaces:**
- Consumes: `crypto.Box.SealAAD/OpenAAD` (`Sealer` interface declared locally, like credentials does).
- Produces (package `ca`):
  - `type CA struct` with `Ensure(ctx context.Context) error` — loads the CA from the store or generates and stores it; `Issue(ctx context.Context, orgID *uuid.UUID, zoneID uuid.UUID, workerName string) (certPEM, keyPEM []byte, serial *big.Int, err error)`; `Pool() (*x509.CertPool, *x509.Certificate)`; `VerifyClient(rawCerts [][]byte) (*ClientIdentity, error)`.
  - `type ClientIdentity struct{ Serial *big.Int; OrgID *uuid.UUID; ZoneID uuid.UUID; WorkerName string }`.
  - Store interface: `Load(ctx) (sealed []byte, found bool, err error)`, `Save(ctx, sealed []byte) error`.
- Cert details (binding): ECDSA P-384 key, certificate `pulsix-worker <name>`, 825-day validity, extensions: `pulsix-org` / `pulsix-zone` as URI SANs (`urn:pulsix:org:<uuid>`, `urn:pulsix:zone:<uuid>`), KeyUsage DigitalSignature, ExtKeyUsage ClientAuth. Server certs (for the gRPC listener) get ExtKeyUsage ServerAuth and the listen host in DNS SANs.

`internal/ca/ca.go` implements `New`, `Ensure`, `Issue`, `Pool`, `VerifyClient`, `NewSerial` exactly to the interface above. Key implementation points:

- `Ensure`: `Load`; when found, `OpenAAD(sealed, []byte("ca:<common-name>"))` yields the JSON `caBlob{KeyPEM, CertPEM}`; parse and keep both. When not found, generate ECDSA P-384 self-signed root (`SerialNumber = NewSerial(rand)`, 3650 days, `IsCA: true`, `KeyUsageCertSign|KeyUsageCRLSign|KeyUsageDigitalSignature`), seal the blob, `Save`, and return `ErrCASealed` wrapped errors on crypto failures.
- `Issue`: fresh ECDSA P-384 key; template with the CN `pulsix-worker <name>` (or `pulsix-manager` + `IsCA: false`, `ExtKeyUsageServerAuth` and DNS SAN `ListenHost` when `orgID == nil && workerName == ""` — the gRPC server certificate path), the URI SANs, `NewSerial`, 825 days; sign with the root; return PEM blocks.
- `VerifyClient`: `x509.CertificateRequest`-free direct parse of each raw cert, verify against the root with `x509.NewCertPool` + `VerifyOptions{KeyUsages: []x509.ExtKeyUsage{ExtKeyUsageClientAuth}}`, then extract the URI SANs into `ClientIdentity` (`uuid.Parse` of the suffix after `urn:pulsix:org:`/`urn:pulsix:zone:`; a cert without a zone SAN or with a malformed one is `ErrBadIdentity`).
- `NewSerial(rand io.Reader) *big.Int`: 63-bit positive (`rand.Int(rand, new(big.Int).Lsh(big.NewInt(1), 63))`).
- The `Sealer` interface and the `rand io.Reader` / `now func() time.Time` are constructor-injected (`ca.New(store, box, cfg, opts ...Option)` with `ca.WithRand(r)`, `ca.WithClock(f)` for tests — same pattern as credentials).

```protobuf
syntax = "proto3";

package pulsix.worker.v1;

import "google/protobuf/timestamp.proto";

service WorkerService {
  // ClaimJob atomically claims one queued job of one of the worker's zones
  // (SELECT ... FOR UPDATE SKIP LOCKED) and returns its full payload,
  // including the rendered inventory snapshot and revealed credential
  // secrets. Empty response with no job means "queue empty".
  rpc ClaimJob(ClaimJobRequest) returns (ClaimJobResponse);
  // RunEvents streams a run's events after a successful claim. The worker
  // sends events; the manager may answer with a cancel directive. Closing
  // the stream without a terminal event makes the manager re-queue the job.
  rpc RunEvents(stream RunEvent) returns (stream ManagerDirective);
  // ReportResult is the terminal unary call: the worker reports the final
  // status and per-host stats. Sent after the last RunEvents message.
  rpc ReportResult(ReportResultRequest) returns (ReportResultResponse);
}

message ClaimJobRequest {
  string version = 1;                // worker build version, recorded on the job
  repeated string zone_ids = 2;      // the zones this worker serves (uuids)
}

message ClaimJobResponse {
  // job is empty when the queue has nothing for these zones.
  Job job = 1;
}

message Job {
  string id = 1;                     // uuid
  string kind = 2;                   // run | adhoc | connection_test | bootstrap | rotate_key | sync_repo
  string org_id = 3;                 // uuid
  string zone_id = 4;                // uuid
  string template_id = 5;            // uuid, empty for non-run kinds
  string playbook = 6;               // inline YAML or "repo:<repo-id>:<subpath>"
  string limit = 7;
  map<string, string> extra_vars = 8;   // JSON-encoded values
  string ssh_username = 9;
  // inventory_doc is the dynamic-inventory JSON with secrets revealed.
  string inventory_doc = 10;
  // connections maps hostname to the rendered Connection JSON.
  map<string, string> connections = 11;
  // credentials maps credential uuid to the revealed Secret JSON. Only
  // credentials the snapshot references. Never logged.
  map<string, string> credentials = 12;
  // host_keys maps hostname to the pinned public-key fingerprint
  // ("SHA256:..."), present when the host has a pin the worker must verify.
  map<string, string> host_keys = 13;
  // kind_payload carries kind-specific JSON (bootstrap login, rotation
  // keys, adhoc argv). Never logged.
  string kind_payload = 14;
  string worker_token = 15;          // echoes the claim for stream binding
}

message RunEvent {
  string job_id = 1;
  uint64 seq = 2;
  string host = 3;
  string task = 4;
  string state = 5;                  // ok | failed | skipped | changed | unreachable | stdout | run_start | run_end
  string payload = 6;                // JSON
  google.protobuf.Timestamp at = 7;
}

message ManagerDirective { bool cancel = 1; }

message ReportResultRequest {
  string job_id = 1;
  string status = 2;                 // succeeded | failed | cancelled | error
  string stats = 3;                  // JSON: per-host ok/failed/skipped/changed counts
  string error = 4;                  // human-readable failure reason, empty on success
}

message ReportResultResponse {}
```
