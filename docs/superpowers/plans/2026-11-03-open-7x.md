# Open v1.0 Items (7.3, 7.37, 7.47, 7.48, 7.63) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After a restore, agents and workers reconnect on their own; upgrades are guarded and documented; backups survive stalls and leftovers; the review leftovers are closed; the release job runs in a protected environment.

**Architecture:** Certificate adoption sits behind the existing serial lookup in the gRPC interceptor and is bounded by a restore marker the restore writes. A schema guard runs before every migrate; version skew is a pure function surfaced through API and SPA. Backup robustness lives in the backup service's run path and ticker.

**Tech Stack:** Go 1.27 (pgx v5, sqlc, goose, grpc-go), PostgreSQL 18 + TimescaleDB, React/TypeScript SPA (Vitest), GitHub Actions YAML.

**Spec:** `docs/superpowers/specs/2026-11-03-open-7x-design.md` (sections 1–5 map to backlog 7.47, 7.3, 7.48, 7.63, 7.37).

## Global Constraints

- Everything in the repository is English; user-visible SPA strings in English and German (`web/src/i18n/en|de/*.ts`).
- Conventional Commits; every commit ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit only the task's own files.
- TDD: failing test first, watched failing, then the minimal change.
- Tests per package with a timeout (`go test -race -count=1 -timeout 900s ./internal/<pkg>/`; `internal/api` needs `-timeout 1800s`). Never one whole-module `go test ./...`. Full suite: `make test`.
- Before every commit: `golangci-lint run` (0 issues) and `gofmt -s -l .` (no output).
- SPA: `PATH=$HOME/.nvm/versions/node/v24.14.0/bin:$PATH`; in `web/`: `npx vitest run <file>`, `npx eslint <files>`, `npx tsc -b`; OpenAPI types via `npm run api:gen`. No prettier.
- sqlc is not installed as a binary: `go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 generate`, then `... diff` must be clean.
- Migrations are additive (a new file each; never edit a released one); every migration has a working Down.
- Database tests use `internal/db/testdb`. Only touch Docker containers the tests start themselves.
- Backlog rows and the end-user docs in `NoiXdev/noix-docs` are updated by the controller after the branch. The GitHub environment for 7.37 is created by the controller.

## Review Focus

1. No restore ever happened (no marker): an unknown serial is refused exactly as today (Task 2, Task 3 tests).
2. A certificate issued before the backup, or after the restore, is never adopted even if everything else matches (Task 2, Task 3 tests).
3. A worker whose row is revoked, or an agent name that matches two hosts, is refused (Task 2, Task 3 tests).
4. A development build (`dev`) or an empty version never shows an "update required" badge (Task 6 test).
5. A backup that is slow but steadily progressing for longer than 10 minutes is not cancelled (Task 8 test).
