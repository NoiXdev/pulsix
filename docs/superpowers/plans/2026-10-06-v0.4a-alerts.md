# Pulsix v0.4a — Alerts and their lifecycle implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the rule engine's state transitions into durable, acknowledgeable
alert episodes with snooze, silence and a timeline — stopping short of any
notification, which is v0.4b.

**Architecture:** A new `internal/alerts` package decides and a store executes:
`Reconcile` is pure and answers "what must change", `Mute` is pure and answers
"is this silent and why". The evaluator calls the package through an
`AlertSink` interface it declares itself, writing in the host transaction it
already holds, so alerts and states can never disagree. A central per-tick
sweep closes alerts whose subject disappeared.

**Tech Stack:** Go 1.27, pgx v5, sqlc, goose, huma v2, testcontainers-go;
React 19, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-06-v0.4a-alerts-design.md`

## Global Constraints

- Layering per `CLAUDE.md`: handlers decode → one service call → encode, and
  never touch `gen.Queries`; services depend on interfaces declared next to
  them; time is injected.
- Migrations are **additive only**. New migrations are `00049` and `00050`.
- RLS on every new table as a policy pair in 00037's shape:
  `org_isolation` with `USING (org_id = NULLIF(current_setting('pulsix.org_id', true), '')::uuid)`
  and `org_isolation_bypass` with
  `USING (current_setting('pulsix.org_id', true) IS NULL OR current_setting('pulsix.org_id', true) = '')`,
  after `ENABLE` **and** `FORCE ROW LEVEL SECURITY`.
- Every table carrying tenant data has its **own** `org_id`; RLS cannot reach
  through a foreign key.
- Severity values are `rules.State` — `ok`, `warn`, `crit`, `unknown`. Order
  comparisons use `rules.StateRank`, never string comparison.
- Conventional Commits, footer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Gates before every commit: `make test` (the groups in `scripts/test-groups.sh`,
  never a bare `go test ./...`) and `golangci-lint run`.
- Coverage floors: Go ≥ 80 %, SPA ≥ 70 %. `internal/alerts` targets ≥ 90 %,
  since it is pure logic with no excuse.
- German UI strings only where the surrounding components already use them;
  code, comments and identifiers are English.

## Review Focus

Five things the spec implies, that no task's obvious test would catch, most
likely to bite first. Each one's test is named in the task that owns the code.

1. **A tuple going `unknown` while its alert is open at `crit`.** The host goes
   dark; every tuple flips to `unknown`. The open `crit` alert must keep its
   severity, must **not** adopt `unknown`, and must **not** close — `unknown`
   is not `ok`, and decision 4 handles it at the host. Without this the fleet's
   worst alerts silently become `unknown` the moment an agent dies. Test in
   Task 2.
2. **`snooze_until_change` never clearing.** An unbounded snooze that nothing
   resets mutes the alert forever. Any severity change must clear it. Test in
   Task 2.
3. **A re-opened subject inheriting an old acknowledgement.** Subject goes bad,
   is acknowledged, resolves, goes bad again. The new alert is a new row and
   must start unacknowledged; a store that reuses or copies the closed row
   would silence a fresh incident. Test in Task 5.
4. **An expired snooze still reporting muted.** `snoozed_until` in the past
   must yield `Muted = false`, not a mute that ended. Test in Task 4.
5. **Two mutes ending at the same instant.** The reported reason must be
   deterministic, not slice-order dependent. Test in Task 4.

- [ ] **Step 3: Write the queries and the store**

The sweep is one statement, driven by open alerts, not by states:

```sql
-- name: SweepStaleAlerts :execrows
UPDATE alerts a SET closed_at = @now, closed_reason = 'stale'
WHERE a.closed_at IS NULL AND a.scope = 'tuple'
  AND NOT EXISTS (
    SELECT 1 FROM check_states s
    WHERE s.host_id = a.host_id AND s.check_key = a.check_key
      AND s.item = a.item AND s.metric = a.metric);
```

The peak uses the rank, not string order:

```sql
-- name: RaiseAlertSeverity :exec
UPDATE alerts SET severity = @severity,
  peak_severity = CASE WHEN @severity_rank::int > (
    CASE peak_severity WHEN 'warn' THEN 1 WHEN 'unknown' THEN 2 WHEN 'crit' THEN 3 ELSE 0 END)
    THEN @severity ELSE peak_severity END,
  snooze_until_change = CASE WHEN @clears_snooze::boolean THEN false ELSE snooze_until_change END
WHERE id = @id AND org_id = @org_id;
```

The rank in SQL must match `rules.StateRank` exactly; a test asserts the two
agree for all four states rather than trusting the duplication.

### Task 7: Wire the sink into the evaluator

**Files:**

  `Tick`, `evaluate`), `cmd/` wherever `rules.NewTicker` is constructed

**Interfaces:**
- Produces, in `internal/rules`:

```go
type AlertSink interface {
	// Apply runs inside the evaluator's transaction, per host.
	Apply(ctx context.Context, tx pgx.Tx, in AlertInput) error
	// Sweep runs once per tick, outside any host's transaction.
	Sweep(ctx context.Context, now time.Time) error
}

func NewTicker(store EvalStore, alerts AlertSink, opts ...TickerOption) *Ticker
```

`AlertInput` already exists from Task 2; this task adds only the interface and
the wiring.

`alerts` is **positional and required**, not a `TickerOption` — the same ruling
`internal/items` got in v0.3b-3, so a forgotten wire fails the build instead of
silently disabling half the alerting. `NewTicker` panics on a nil sink, the way
a nil store would.

- [ ] **Step 1: Write the failing tests**

```go
func TestEvaluateFeedsTheAlertSinkInTheHostTransaction(t *testing.T) {
	sink := &fakeSink{}

		t.Fatalf("sink called %d times, want once per evaluated host", len(sink.calls))
	}
	got := sink.calls[0]

```

- [ ] **Step 3: Wire it**

In `evaluate`, hoist the result and hand the sink the claim's transaction —
which lives on the context, not in a parameter:

```go
res := Evaluate(snap)
if err := t.store.Apply(ctx, d, res); err != nil {
	t.log.ErrorContext(ctx, "apply evaluation; leaving the host due for the next tick",
		"org", d.OrgID, "host", d.HostID, "err", err)

}
tx, ok := claimTx(ctx)
if !ok {
	return errNoClaimTx
}
if err := t.alerts.Apply(ctx, tx, AlertInput{

}
```

In `Tick`, after `ProcessDue` returns, call `t.alerts.Sweep(ctx, now)` and log
its error without failing the tick — a sweep that could not run is a delayed
