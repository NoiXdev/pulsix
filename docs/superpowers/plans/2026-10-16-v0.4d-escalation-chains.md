# Escalation chains Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After N minutes without an acknowledgement, an alert route tells the next set of channels — and stops the moment somebody is demonstrably dealing with it.

**Architecture:** A second, time-driven pass in the existing alert follower, beside the event-driven one it already runs. Escalation state is an anti-join ledger keyed by `(alert, route, position)`: a step is due when it has no row and its delay has elapsed since the chain last became urgent, and writing the row is what makes it fired. Nothing new is stored for the clock — every anchor it reads is already on the alert, its events, or the maintenance occurrences the pass computes anyway.

**Tech Stack:** Go 1.27.1, pgx v5, sqlc 1.31.1, goose, huma v2, PostgreSQL 18, React 19 + TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-16-v0.4d-escalation-chains-design.md`

## Global Constraints

- Migrations are additive only. The one constraint replacement in this plan (`alert_events.kind`) widens an allowed set and invalidates no existing row; its migration says so in a comment.
- Every tenant table carries `org_id`, composite foreign keys `(org_id, id)`, and the `org_isolation` / `org_isolation_bypass` policy pair with `ENABLE` **and** `FORCE ROW LEVEL SECURITY` — copy the `DO` block at the foot of `00054_notification_schedules.sql`.
- Layers, strictly: `internal/api` decodes and calls a service; services hold business rules and no SQL; stores are sqlc behind a small interface declared next to the service. Handlers never touch `gen.Queries`.
- Time and randomness are injected. The follower already has a `now func() time.Time`; every timing test drives it and none sleeps.
- Errors wrap with context (`fmt.Errorf("claim step: %w", err)`); services return `ErrNotFound` / `ErrForbidden` for handlers to map.
- Coverage gates: Go ≥ 80 % overall, ≥ 90 % for auth, tenancy and db. SPA ≥ 70 %.
- Run the race suite as `make test`, never a whole-module `go test ./...`. `golangci-lint run` must pass before every commit; it carries gofmt.
- Conventional Commits, footer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`. Commit after each task. Do not push, do not merge.
- `node` is not on PATH for SPA work: `export PATH="$HOME/.nvm/versions/node/v24.14.0/bin:$PATH"`, run from `web/`.
- End-user documentation lives in `NoiXdev/noix-docs` on branch `pulsix`; this feature changes user-visible behaviour, so it is updated in the same work item (Task 9).

## Review Focus

Five things the spec implies that a task could ship without noticing, most likely to bite first. Each has a test assigned to the task that owns the code.

1. **Two routes, two chains, one alert.** Decision 1 makes this correct, and the ledger's key allows it — but a shared `alert_id` is exactly where an over-eager `WHERE` turns two chains into one, or lets one route's step suppress the other's. Pinned in Task 4.
2. **A step that reaches nobody.** Its rotation is empty, or its last channel was deleted. v0.4b already decided a route that reaches nobody survives and says so rather than vanishing; a step must do the same — fire, record, and not wedge the chain behind a rung that can never be climbed. Pinned in Task 6.
3. **The same step firing twice.** Two managers tick concurrently, or one tick runs long and overlaps the next. The advisory lock and the primary key both guard it, but only a test proves the second attempt is a no-op rather than an error that aborts the pass. Pinned in Task 4.
4. **An alert that closes mid-delay.** The chain must be silent afterwards — not merely "not due yet", but silent for good, including after a restart that re-reads the open alert set. Pinned in Task 6.
5. **Clearing `acknowledged_severity` reaches further than escalation.** The alert list's acknowledged filter, the host card and the timeline all read that column, and none of them asked for this change. Pinned in Task 2.

-- +goose Up

-- A route's escalation ladder (v0.4d, backlog 4.9). Position 0 is NOT
-- stored: it is the route's own channels or rotation, delivered at once,
-- exactly as before this migration. That is what lets every existing
-- route keep its behaviour without being migrated.
CREATE TABLE alert_route_steps (
  org_id        uuid NOT NULL,
  route_id      uuid NOT NULL,
  position      integer NOT NULL CHECK (position >= 1),
  -- Relative to the previous step's real firing, never absolute from the
  -- alert (spec decision 3) — which is why a chain can never arrive all
  -- at once after a long silence.
  delay_seconds integer NOT NULL CHECK (delay_seconds > 0),
  -- A step names a rotation or a fixed channel set, the same two sources
  -- the route itself offers. NULL here means "see
  -- alert_route_step_channels".
  rotation_id   uuid,
  PRIMARY KEY (route_id, position),
  FOREIGN KEY (org_id, route_id) REFERENCES alert_routes (org_id, id) ON DELETE CASCADE,
  FOREIGN KEY (org_id, rotation_id) REFERENCES oncall_rotations (org_id, id) ON DELETE SET NULL (rotation_id)
);

CREATE TABLE alert_route_step_channels (
  org_id     uuid NOT NULL,
  route_id   uuid NOT NULL,
  position   integer NOT NULL,
  channel_id uuid NOT NULL,
  PRIMARY KEY (route_id, position, channel_id),
  FOREIGN KEY (route_id, position) REFERENCES alert_route_steps (route_id, position) ON DELETE CASCADE,
  FOREIGN KEY (org_id, channel_id) REFERENCES notification_channels (org_id, id) ON DELETE CASCADE
);

-- The anti-join ledger. A step is due when it has no row here; writing
-- the row is what makes it fired. Position 0 is the base: the moment the
-- route first really delivered for this alert, observed rather than
-- computed from a cron expression (spec decision 3).
CREATE TABLE alert_escalations (
  org_id   uuid NOT NULL,
  alert_id uuid NOT NULL,
  route_id uuid NOT NULL,
  position integer NOT NULL CHECK (position >= 0),
  fired_at timestamptz NOT NULL,
  PRIMARY KEY (alert_id, route_id, position),
  FOREIGN KEY (org_id, alert_id) REFERENCES alerts (org_id, id) ON DELETE CASCADE,
  FOREIGN KEY (org_id, route_id) REFERENCES alert_routes (org_id, id) ON DELETE CASCADE
);

-- The pass asks "which open alerts have an unfired step", so the index
-- leads with the alert.
CREATE INDEX alert_escalations_alert_idx ON alert_escalations (org_id, alert_id, route_id, position);

-- 'escalated' is the eighth kind; the other seven are 00049's own. This
-- is a DROP and ADD of the constraint rather than an ALTER, because
-- Postgres has no "widen a CHECK" — but it is additive in effect: every
-- existing row satisfies the new set, so nothing is invalidated.
ALTER TABLE alert_events DROP CONSTRAINT alert_events_kind_check;
ALTER TABLE alert_events ADD CONSTRAINT alert_events_kind_check
  CHECK (kind IN ('opened', 'severity_raised', 'acknowledged', 'ack_voided',
                  'snoozed', 'unsnoozed', 'closed', 'escalated'));

-- +goose StatementBegin
DO $$
DECLARE t text;
BEGIN
  FOREACH t IN ARRAY ARRAY['alert_route_steps', 'alert_route_step_channels', 'alert_escalations'] LOOP
    EXECUTE format('ALTER TABLE %I ENABLE ROW LEVEL SECURITY', t);
    EXECUTE format('ALTER TABLE %I FORCE ROW LEVEL SECURITY', t);
    EXECUTE format('CREATE POLICY org_isolation ON %I USING (org_id = NULLIF(current_setting(''pulsix.org_id'', true), '''')::uuid)', t);
    EXECUTE format('CREATE POLICY org_isolation_bypass ON %I USING (current_setting(''pulsix.org_id'', true) IS NULL OR current_setting(''pulsix.org_id'', true) = '''')', t);
  END LOOP;
END $$;
-- +goose StatementEnd

-- +goose Down
DROP TABLE alert_escalations;
DROP TABLE alert_route_step_channels;
DROP TABLE alert_route_steps;
ALTER TABLE alert_events DROP CONSTRAINT alert_events_kind_check;
ALTER TABLE alert_events ADD CONSTRAINT alert_events_kind_check
  CHECK (kind IN ('opened', 'severity_raised', 'acknowledged', 'ack_voided',
                  'snoozed', 'unsnoozed', 'closed'));
```

// Step is one rung of a route's ladder. Position 0 is never a Step: it is
// the route's own channels, and only the ledger records it.
type Step struct {
	Position     int
	Delay        time.Duration
	RotationID   *uuid.UUID
	ChannelIDs   []uuid.UUID
}

// ChainState is everything the decision needs about one (alert, route)
// pair, read before any of it is written.
type ChainState struct {
	Steps        []Step    // ordered by Position, 1..n
	FiredUpTo    int       // highest position with a ledger row; -1 when even the base is missing
	LastFiredAt  time.Time // fired_at of FiredUpTo; zero when FiredUpTo is -1
	LastUrgentAt time.Time // most recent severity_raised / ack_voided / end-of-mute; zero if none
}

// DueStep reports the one step that should fire now, and whether there is
// one. It never returns more than one: a chain climbs a rung at a time,
// because each rung's clock starts when its predecessor really fired.
func DueStep(cs ChainState, now time.Time) (Step, bool)
```

```go
// DueStep is pure: no clock, no database, no logging — the same shape
// rules.Resolve and alerts.Mute already have, so the timing rules can be
// read and tested without a Postgres container anywhere near them.
func DueStep(cs ChainState, now time.Time) (Step, bool) {
	// The base is the route's first real delivery. Until it exists there
	// is no clock to start: a route that has not yet said anything has
	// nothing to escalate from (spec decision 3).
	if cs.FiredUpTo < 0 {
		return Step{}, false
	}
	next := cs.FiredUpTo + 1
	for _, s := range cs.Steps {
		if s.Position != next {
			continue
		}
		// The anchor is the later of the previous rung's real firing and
		// the last thing that made this alert newly urgent, so a chain
		// resuming after a pause gives the next rung its full delay
		// instead of firing at once (spec decision 5).
		anchor := cs.LastFiredAt
		if cs.LastUrgentAt.After(anchor) {
			anchor = cs.LastUrgentAt
		}
		if !now.Before(anchor.Add(s.Delay)) {
			return s, true
		}
		return Step{}, false
	}
	return Step{}, false
}
```

- [ ] **Step 4: Write the pass**

`escalatePass` reads every chain needing attention, then for each one:

1. skips it when `alerts.Mute` reports the alert muted — and folds the occurrence's end into `ChainState.LastUrgentAt`, which is the one anchor the SQL could not see;
2. skips it when the alert is acknowledged or its severity is outside the route's set;
3. asks `DueStep`;
4. resolves the step's channels through `channelsOf`;
5. `ClaimStep` — and if it reports false, does nothing further for that chain this tick;
6. enqueues through the existing outbox and writes the `escalated` event with the position and the channels in its payload.

Read the whole working set before writing any of it, for the same reason the event pass does: a step claimed in this pass must not be re-resolved against the identical `now` later in the same tick.
