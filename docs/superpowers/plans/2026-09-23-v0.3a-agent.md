# Pulsix v0.3a Agent & Enrollment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Linux agent binary that enrolls with a one-time token (binding to a pre-created host or creating its own), receives a CA-issued 90-day certificate, holds one persistent mTLS stream to the manager, reports heartbeat and facts with auto tags, and shows its state in the GUI — with the three v0.1 release blockers as the plan's first tasks.

**Architecture:** Agents are a second client-certificate class on the manager's existing gRPC listener (`PULSIX_GRPC_LISTEN`): the spec's agent→worker relay moves to v0.6 (documented delta). `internal/agentapi` mirrors the worker identity machinery — enroll tokens (`pxa1` tokens extending `internal/enrolltoken`), an `agent_certificates` serial registry, certificate renewal, stream revocation — while `cmd/agent` (`internal/agent`) is the counterpart binary: CSR → mTLS → persistent stream with backoff, facts via gopsutil, first-start-only enrollment. Facts land in `hosts.facts` and upsert `host_tags (source='fact')` beneath manual tags.

**Tech Stack:** as v0.2/0.2a (Go 1.27, chi v5, huma v2, pgx v5, sqlc, goose, testcontainers-go, buf, React 19, TanStack, Vitest) plus `github.com/shirou/gopsutil/v4` (newest; verify pin at write time).

Spec: `docs/superpowers/specs/2026-09-23-v0.3a-agent-design.md` (binding for decisions).

## Decisions (from the spec — binding)

- Agent→Manager directly; spec §8's relay delta recorded in the architecture spec (Task 12 amends it).
- One active agent per host; `host_agents` row replaced on re-enrollment (previous serial revoked).
- Token flag: `host_id` set → bind; unset → agent creates the host (name order: token name hint → `PULSIX_AGENT_NAME` → OS hostname; hosts.Create rules validate; conflict = enrollment failure).
- First-start-only enrollment: cert persisted in the data dir; restart reconnects, skips Enroll; expired cert without token fails loudly with the remediation.
- 90-day certs, renewal at 2/3 lifetime via `Renew` (cert-authenticated — NOT in the unauthenticated set; only `Enroll` is).
- Certificate SAN: `urn:pulsix:org:<uuid>` only; CN `pulsix-agent <name>`; the absence of the zone SAN distinguishes agent from worker identity in `ca.VerifyClient`.
- Facts at start + every 6 h; heartbeat every 30 s; GUI marks unknown after 3 × interval (computed from `last_seen` age at read time, no cron).
- Auto tags `os`, `arch`, `virt` upserted with `source='fact'`; a manual tag of the same key wins (upsert skips keys that already have a manual row).
- Enroll rate-limited per address (the shared-bucket pattern of 2.67, reusing grpcsrv's Enroll limiter mechanics); install/binary routes public but rate-limited, query params never logged.
- Permissions: `agents.read` (viewer), `agents.write` (operator) for tokens/revocation; enrollment itself is unauthenticated gRPC.

## Task briefs

### Task 1: Rate limiting on auth endpoints (1.20)

Read the backlog row + `internal/api` auth handlers. Add per-address rate limiting to exactly: `POST /auth/login`, TOTP verify, passkey finish (ceremony start/finish as applicable), `POST /invites/accept` — the endpoints 1.15/1.20 name. Implementation follows the codebase's existing limiter mechanics (the per-address token bucket from the webhook/Enroll work — find `internal/clientip` + the rate limit pattern used for hooks and reuse it; do NOT invent a new limiter). Config: `PULSIX_AUTH_RATE_LIMIT` (requests per minute per address, default sane value documented in config comments); limits apply per route family, count only failed attempts where the mechanism allows (match the hook per-address semantics). 429 with `Retry-After`. Tests (apitest): the limit trips, resets per address, other routes unaffected, disabled via config=0 for tests where needed. Audit untouched (auth routes are allowlisted already). Update BACKLOG rows 1.15/1.20 to done.

### Task 2: Reapers for expired ceremonies and sessions (1.21)

A periodic reaper (same shape as the v0.2b job reaper: ticker, injected interval default 1 h, advisory-locked against multi-manager duplicates) deletes `webauthn_ceremonies` rows older than their TTL and `sessions` rows expired past a grace window (expired sessions are already unauthenticated at read time — the reaper only bounds growth; pick the windows: ceremonies max-age per the auth package's own constant, sessions expiry + 7 d retention). Integration test: expired rows removed, live rows untouched, concurrent reapers don't double-run (advisory lock). Unit tests with a fake clock. BACKLOG row 1.21 done.

### Task 3: Touch throttle and static-asset session skip (1.22)

`TouchLastUsed` becomes throttled (at most once per minute per session — in-memory map or SQL predicate `WHERE last_used_at < now() - interval '1 minute'`; prefer the SQL predicate so it holds across managers) and the session-lookup middleware skips entirely for static asset paths (the SPA embed routes; find the static handler and short-circuit the session middleware there). Tests: two rapid requests → one write (integration), static asset path bypasses auth without breaking protected routes. BACKLOG row 1.22 done.

### Task 4: Agent proto

Create `proto/pulsix/agent/v1/agent.proto` + buf regen into `internal/pb/agentpb/`. Service contract (from the spec, verbatim):

```protobuf
service AgentService {
  rpc Enroll(EnrollRequest) returns (EnrollResponse);
  rpc Renew(RenewRequest) returns (EnrollResponse);
  rpc AgentStream(stream AgentMessage) returns (stream ManagerMessage);
}
message EnrollRequest { string token = 1; string csr_pem = 2; string name = 3; string version = 4; }
message EnrollResponse { string cert_pem = 1; string ca_pem = 2; string host_id = 3; }
message RenewRequest { string csr_pem = 1; }          // identity from the client certificate
message AgentMessage { oneof body { Heartbeat heartbeat = 1; Facts facts = 2; } }
message Heartbeat { string version = 1; }
message Facts { map<string, string> values = 1; }
message ManagerMessage { bool ack = 1; }
```

- `buf lint` clean; `Renew` is certificate-authenticated (NOT unauthenticated); only `AgentService/Enroll` joins `unauthenticatedMethods`.
- Test: `internal/pb/agentpb` compiles, one message round-trip, service registration compiles.
- Commit: `feat(proto): agent enrollment and stream contract`.
