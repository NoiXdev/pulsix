# Host view overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the hosts list, the add/edit dialog and the host detail page (sidebar + sections, layout B), replace every boolean checkbox with a shared switch, and extract the building blocks other views will reuse.

**Architecture:**
- **Backend (additive):** one transactional host write that sets the host fields, the jump-host mode and the tags together, used by both `POST /hosts` and `PATCH /hosts/{id}`. A `host_id` filter on the runs list.
- **SPA:** presentational building blocks go in `web/src/ui`; the host pages in `web/src/features/hosts` compose them through `web/src/api` hooks.

**Tech Stack:** Go 1.27 (huma, sqlc, goose, pgx), Postgres 18; React + TypeScript, TanStack Router/Query, Tailwind, Vitest, openapi-typescript (`npm run api:gen`).

**Spec:** `docs/superpowers/specs/2026-11-03-host-view-design.md`. The "Controller's calls" section is binding.

## Global Constraints

- Layering per `CLAUDE.md`:
  - **Go:** `internal/api` (decode → service → encode) → `internal/<domain>` services (no HTTP, no SQL) → stores (sqlc behind an interface).
  - **SPA:** `src/api` → `src/features` → `src/ui`. `src/ui` has no data fetching; a value import from `src/api` there fails lint.
- Migrations are additive only. The next free number is `00079`.
- English in code and comments. Every new user-visible string goes in both `web/src/i18n/en/*.ts` and `web/src/i18n/de/*.ts`.
- Go tests: `make test` style groups, never one whole-module `go test ./...`. Run only the touched packages with `-race` and a timeout (`internal/api` with `-timeout 1800s`, others `-timeout 900s`). `golangci-lint run` and `gofmt -s -l .` must be clean before each commit.
- SPA: `cd web && export PATH=$HOME/.nvm/versions/node/v24.14.0/bin:$PATH`. Run `npx vitest run <paths>`, `npx eslint src`, `npx tsc -b` before each commit. After any API change, run `npm run api:gen` and commit `web/src/api/schema.d.ts`.
- sqlc: `go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 generate`.
- Commits: Conventional Commits, footer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, never tag.
- Every card and section grows with its content. Nothing on the host page may be clipped. `Card` in `web/src/ui/table.tsx` is `overflow-hidden` inside flex columns, which is today's bug.
- A host that is not monitored shows no monitoring numbers or check lists. A click on a list row never changes state.

## Review Focus

1. **Row menu inside a clickable row:**
   - opening the ⋯ menu or choosing an item never also navigates;
   - Enter on a focused row navigates;
   - Cmd-click or middle-click on a row opens a new tab, because the row is a real link.

   *(Task 6 tests.)*
2. **Stale edit:** someone else saved the host first, so `PATCH` answers 412 or a revision mismatch. The dialog stays open with the input kept and says the host changed meanwhile. *(Task 5 test.)*
3. **Explicit jump host that does not exist or belongs to another org:** the API answers 404 or 422, never 500, and nothing is written, not even the host fields. *(Task 2 test.)*
4. **Monitored host with no readings yet** (no agent, fresh host): the State section says there are no readings yet. It is neither empty nor broken. *(Task 7 test.)*
5. **Monitoring switched off while alerts are still open:** the hint card shows "N alerts are still open from before", with a link to `/o/$org/alerts?host=<id>`. *(Task 7 test.)*

### Task 2: One transactional host write with jump host and tags (backend)

**Files:**
- Modify: `internal/hosts/service.go` (`HostInput`, `CreateHost`, `UpdateHost`, the `Store` interface)
- Modify: `internal/hosts/store_sql.go`
- Modify: `internal/db/queries/sshconf.sql`, adding the query `UpsertHostBastion`
- Modify: `internal/api/host_handlers.go` (`hostInputBody`, `hostDTO`, permissions)
- Regenerate: `internal/db/gen`, `web/src/api/schema.d.ts`
- Test: `internal/hosts/service_test.go`, `internal/hosts/store_sql_test.go`, `internal/api/host_handlers_test.go`

**Interfaces:**
- Produces, in Go (`internal/hosts`):
  ```go
  // Jump is a host's jump-host choice; Mode is "inherit", "none" or "explicit".
  type Jump struct {
      Mode      string
      BastionID *uuid.UUID // set iff Mode == "explicit"
  }
  type HostInput struct {
      Name, Address string
      ZoneID        uuid.UUID
      Managed, Monitored bool
      Jump *Jump  // nil = leave unchanged (create: inherit)
      Tags *[]Tag // nil = leave unchanged (create: none)
  }
  ```
  `CreateHost` and `UpdateHost` keep their signatures. The store writes the host row, the jump host (only `bastion_mode` and `bastion_id` in `host_ssh`; username, port and credential are untouched, and a missing row is inserted with defaults) and the tags in **one** transaction (`db.WithOrg`). A failure in any part writes nothing.
  - An unknown `BastionID`, or one from another org (the composite FK rejects it), maps to `ErrNotFound`.
  - Mode and BastionID that do not agree map to `ErrInvalidInput`.
  - Tags go through the existing `validateTags`.
- Produces, on the wire (additive):
  - The `POST`/`PATCH` body gains `jump?: {mode: "inherit"|"none"|"explicit", bastion_id?: string}` and `tags?: [{key, value}]`.
  - `hostDTO` gains `revision` (int64), which the SPA needs for `If-Match`.
  - If the body carries `jump`, the route additionally requires `tenancy.PermInventoryWrite`, the permission of `PUT /hosts/{id}/ssh` today. `tags` needs only `PermHostsWrite`, as `PUT /hosts/{id}/tags` does.

- [ ] **Step 1: Write the failing tests.**
