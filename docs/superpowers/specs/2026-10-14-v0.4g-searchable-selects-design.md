# v0.4g — Searchable selects, with quick-create where it saves a form

Status: approved, not yet planned
Backlog: 1.43
Milestone: v0.4g (GUI, independent of the alerting line)

## The problem

Every picker in Pulsix is a native `<select>`. That was right when an
organization had three hosts and two credentials; it is wrong now. A
rule dialog's host picker lists every monitored host, a route dialog's
channel picker every channel, and an inventory group's parent picker
every group in the tree. None of them can be searched: the only way to
find an entry is to scroll, or to know the first letter and hope.

The second half is worse and quieter. A form that needs a credential
you have not created yet is a dead end: you cancel, lose what you
typed, go to Credentials, create it, come back, and start over.

## Decisions

### 1. Every select, not only the long ones

All 76, including the fixed enums. Two different select widgets inside
one dialog — `RepoDialog` has both a credential picker and a kind enum —
reads as an unfinished migration, and the rule "searchable above N
options" has to be re-litigated at every new field. One widget, one
answer.

The cost is accepted knowingly: converting the enums is what makes the
test churn 119 rather than roughly 60.

### 2. Downshift, not hand-rolled

`downshift@9.4.0` (peer `react >=16.12.0`, so React 19 is fine; ~5 kB).
It is the first UI dependency in a project with nine runtime packages,
and that is the point of the trade: keyboard interaction, ARIA
`combobox`/`listbox` wiring, focus management and typeahead are exactly
the parts that are subtly wrong when hand-written and only surface with
a screen reader — multiplied here by 76 call sites.

### 3. One mechanism, always `useCombobox`

No "listbox below N options, combobox above it". Options arrive
asynchronously, so a threshold means the widget can change its shape
and keyboard model mid-interaction, while focused. One code path, one
set of tests, one thing for a user to learn. A filter field above three
options is a cosmetic blemish; a picker that rearranges itself under
the cursor is a defect.

### 4. The component stays presentational

`src/ui/Select.tsx` takes its options as a prop and fetches nothing —
the ESLint rule from backlog 3.23 enforces this anyway. Quick-create is
a callback, never a query:

```tsx
interface SelectOption {
  value: string;
  label: string;
  /** Secondary text on the row — a credential's kind, a host's zone. */
  hint?: string;
  disabled?: boolean;
}

interface SelectProps {
  options: SelectOption[];
  value: string;
  onChange: (value: string) => void;
  /** Shown when value is '' — replaces today's "— none —"/"All zones"
   *  empty <option>. Its presence is what makes the field clearable. */
  placeholder?: string;
  id?: string;
  'aria-label'?: string;
  disabled?: boolean;
  invalid?: boolean;
  /** Last row of the list. The feature owns the dialog it opens. */
  create?: { label: string; onSelect: () => void };
}
```

`value`/`onChange` is deliberately the shape 73 of the 76 sites already
use, so those migrations are a mechanical substitution. The three
`register()` sites wrap in react-hook-form's `Controller`.

### 5. Quick-create only where it rescues a form in progress

Added:

| picker | in | creates |
|---|---|---|
| Credential | RepoDialog (both), HostSshCard, TemplateDialog, BastionDialog | credential |
| Zone | AddAgentDialog, AddWorkerDialog, HostsListPage's add-host | zone |
| Jump host | HostSshCard, inventory SettingsTab | bastion |
| Channel | RotationsPage's stand-in row | channel |

Not added: hosts (created by enrolment or the add-host flow, not as a
side effect of a rule), playbooks and job templates (they come from a
repository), monitoring groups (a selector needs thought, not a
two-field dialog), organizations, and every fixed enum.

`RouteDialog`'s channel picker is **not** on the list even though it is
the most obvious candidate: it is a multi-select built from checkboxes,
not a `<select>`, so this sub-project does not touch it at all
(decision 7), and quick-create there would be separate work.

The dialogs mostly exist already as standalone components.
`CreateGroupDialog` already reports its result through `onCreated(id)`;
`AddCredentialDialog`, `BastionDialog` and `ChannelDialog` take only
`onClose` and gain the same callback. The zone form is the exception:
it lives inline inside `HostsListPage` and has to be extracted into
`features/hosts/ZoneDialog.tsx` first.

Nesting: `ui/dialog.tsx` drives a native `<dialog>` with `showModal()`,
and the browser keeps modal dialogs on a stack, so a create dialog
opening above a picker's own dialog is supported. **Task 2 proves this
with a test before any feature depends on it** — if the stack
misbehaves in jsdom or in Chromium, quick-create inside a dialog falls
back to replacing the parent dialog's content, and that answer must be
known before the eleven call sites in the table above assume otherwise.

### 6. Two test helpers carry the migration

`src/test/pickOption.ts` and `web/e2e/pickOption.ts`:

```ts
// Vitest
await pickOption(screen, 'Credential', 'acme-deploy');
// Playwright
await pickOption(dialog, 'Kind', 'SSH key');
```

Each opens the combobox, types enough to narrow, and clicks the row.
Written and tested in Task 3, before any call site needs them, so the
119 edits are one-liners and a fix to the interaction applies in one
place rather than 119.

### 7. Not in this sub-project

Multi-select (route severity sets, group membership) stays as it is.
Virtualized lists: the longest realistic list is hosts, and the host
list is already paginated elsewhere; if a picker ever needs windowing
it gets its own row. Async/remote filtering: every option list here is
already in memory from a query the page made anyway.

## Risks

- **A breadth change with no behavioural anchor.** 76 sites, 119 tests,
  and nothing in the API changes — so a mistake shows up only as a
  picker that no longer picks. Mitigation: per-area tasks, each green
  before the next starts, and the Playwright suite as the end gate
  (it passes today, 17 of 18 journeys, one pre-existing skip).
- **The React Compiler.** The SPA builds with it; downshift's hooks
  must not trip its rules. Verified in Task 1 on the component alone,
  before anything depends on it.
- **Bundle size.** The entry chunk is already 907 kB (244 kB gzipped)
  and warns at build. Downshift adds ~5 kB; removing 76 blocks of
  `<option>` markup gives some of it back. Recorded, not solved here —
  code splitting is its own row.

## Acceptance

- No `<select` element remains under `web/src` outside `Select.tsx`'s
  own implementation. An ESLint `no-restricted-syntax` rule enforces it
  — the same mechanism backlog 3.24 already uses to keep MetricChart out
  of the entry bundle — so the seventy-seventh one fails the build
  instead of waiting to be noticed in review.
- Keyboard: open, type to filter, arrow, Enter, Escape, Tab away — all
  covered by the component's own tests, including that Escape closes
  the list without closing a surrounding dialog.
- Every quick-create picker creates its object and selects it, with the
  parent form's other fields untouched; one test per object kind.
- `npm test`, `tsc -b`, `npm run lint`, the coverage gate and
  `npm run e2e` all pass.
