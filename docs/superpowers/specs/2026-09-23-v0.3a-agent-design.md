# Pulsix v0.3a — Agent & Enrollment design

Status: approved design (2026-09-23), feeds the v0.3a implementation plan.
Extends the architecture spec §8 (Agent) and §5 (host capabilities); deltas against
§8 are recorded under "Deltas to the architecture spec".

## Goal

The agent half of milestone v0.3: a Linux agent binary that enrolls with a
one-time token, receives a client certificate from the internal CA, holds one
persistent mTLS stream to the manager, reports heartbeat and facts, and shows
its state in the GUI — plus the three v0.1 release blockers as the plan's first
tasks. Check definitions, rules and metrics arrive with v0.3b/v0.3c; this plan
lays the stream and the registry they build on.

## Decisions

- **Agents dial the manager directly.** The agent connects to the manager's
  existing gRPC listener (`PULSIX_GRPC_LISTEN`) with a CA-issued client
  certificate — a second certificate class beside the workers, same listener,
  same interceptor pattern, same serial registry shape. No new ports anywhere.
  Spec §8's agent→worker→manager topology (worker-held listener + relay) moves
  to v0.6, when zone workers become the agent-facing tier; recorded as a
  deliberate delta in the architecture spec.
- **Enrollment binds by token flag.** An enrollment token optionally names a
  `host_id`: with one, the agent claims exactly that host row (the operator
  pre-created it); without one, the agent creates a new host row in the token's
  zone — the host name resolves in this order: the token's optional name hint,
  the agent's configured `PULSIX_AGENT_NAME`, the OS hostname; the manager
  validates it with the hosts service's own rules and reports a name conflict as
  a normal enrollment failure the agent surfaces to stderr. Both flows are
  first-class and both are E2E-tested.
- **Enrollment is a first-start concern.** The agent persists its identity
  (certificate and key in the data dir); on restart it reconnects with the
  existing certificate and skips Enroll entirely. A valid Renew replaces an
  expiring certificate in place. A restart that finds an invalid/expired
  certificate without a fresh token fails loudly with the remediation (create a
  new enrollment token).
- **One active agent per host.** `host_agents` carries the binding; a fresh
  enrollment for the same host replaces the row (and revokes the previous
  certificate serial). Revocation ends the agent's streams and clears
  `hosts.monitored` only if no other agent remains — the capability flag is
  operator-controlled, enrollment just reports reality.
- **Certificate lifetime and renewal** follow the worker model (2.23/2.24):
  90-day client certificates, the agent renews at 2/3 lifetime, revoked or
  expired serials are refused. The certificate SAN carries
  `urn:pulsix:org:<org-id>`; the zone rides the token at enrollment and lives in
  the host row, not the certificate.
- **Binaries ship embedded.** The manager image embeds the agent binaries
  (linux/amd64, linux/arm64, `go:embed`) and serves `GET /install.sh` and
  `GET /agents/bin/{os}/{arch}` as public, rate-limited routes, so
  `curl -fsSL https://<manager>/install.sh | sh -s -- --token <t>` works out of
  the box on a self-hosted instance with no external downloads. Image growth
  (~50 MB) is accepted for the single-node story.
- **Facts and auto tags.** The agent reports facts at start and every 6 h
  (collected with `gopsutil`, newest release): OS, kernel, arch, CPU model and
  count, memory, virtualization, agent version, hostname, IPs. The manager
  stores them in `hosts.facts` (existing jsonb) and upserts `host_tags` with
  `source = 'fact'` for `os`, `arch` and `virt`; a manual tag of the same key
  always wins (the upsert skips keys the operator set manually).
- **Stream shape.** One persistent bidirectional stream per agent. Agent →
  manager: heartbeat (version, interval) and facts messages. Manager → agent:
  empty acks in v0.3a; the message union is open for the v0.3b config push
  (versioned config frames) without a proto break. The agent reconnects with
  exponential backoff (1 s → 60 s cap); a missed heartbeat window marks the host
  agent state `unknown` in the GUI after 3 × heartbeat interval.
- **Rate limits** on Enroll follow 2.67's shared-bucket pattern; the new public
  binary routes are rate-limited too and never log the requested token.

## Protocol (workerproto-sibling)

```protobuf
service AgentService {
  // Enroll exchanges a one-time token for a client certificate. Unauthenticated
  // (token-authenticated), rate-limited; refuses unknown, expired or exhausted
  // tokens.
  rpc Enroll(EnrollRequest) returns (EnrollResponse);
  // Renew exchanges a valid client certificate for a fresh one (same identity),
  // mirroring the worker renewal; called at 2/3 certificate lifetime.
  rpc Renew(RenewRequest) returns (EnrollResponse);
  // AgentStream is the persistent mTLS stream: heartbeats and facts go up,
  // manager directives come back (empty in v0.3a).
  rpc AgentStream(stream AgentMessage) returns (stream ManagerMessage);
}

message EnrollRequest { string token = 1; string csr_pem = 2; string name = 3; string version = 4; }
message EnrollResponse { string cert_pem = 1; string ca_pem = 2; string host_id = 3; }
message RenewRequest {}
message AgentMessage {
  oneof body {
    Heartbeat heartbeat = 1;
    Facts facts = 2;
  }
}
message Heartbeat { string version = 1; }
message Facts { map<string, string> values = 1; }
message ManagerMessage { bool ack = 1; }
```

Enrollment flow: agent generates an ECDSA P-256 key pair, sends the CSR (CN
`pulsix-agent <name>`) with the token over plain TLS; the manager validates the
token (org, zone, host binding, count, expiry), issues the certificate (CA
reuse), stores `host_agents` + the serial, flips `hosts.monitored = true`,
returns cert + CA PEM. Renewal is the same flow authenticated by the current
certificate instead of the token. Every claim is audited (`agent.enroll`,
`agent.renew`); the token material never lands in logs or audit summaries.

## Data model (migrations 00037–00039)

- `00037_agents.sql`: `host_agents (host_id PK, org_id FK, agent_name, cert_serial UNIQUE, last_seen, version, created_at)` + `agent_certificates (serial PK, org_id, host_id, revoked_at, created_at)` mirroring `worker_certificates`; RLS pairs.
- `00038_agent_tokens.sql`: `agent_tokens (id, org_id, zone_id, host_id NULL, tags jsonb NULL, max_uses int, uses int, expires_at, created_by, created_at)` generalizing the worker enrollment tokens (the v0.2c `enrolltoken` package is extended, not forked).
- Numbers are the plan's floor; later tasks renumber at write time if the range collides. Facts → auto tags ride the existing `host_tags` (00011) with `source='fact'`.

## GUI

- Host detail: Agent card (version, last seen, certificate expiry, state chip
  ok/unknown after 3 × heartbeat interval; enroll button for pre-created hosts).
- Agents/enrollment page: fleet tokens (no host binding), the list of enrolled
  agents across the org, revoke action per agent (mirrors the Workers page).
- Host list: agent state chip next to the existing capability badges.

## Security

- The CSR endpoint is unauthenticated but token-bound and rate-limited (shared
  bucket pattern of 2.67); install routes are public but rate-limited and never
  log query parameters. Certificates and keys are never logged. The agent's
  private key lives only in its data dir (0600). Revocation ends streams and
  refuses the serial (same interceptor shape as workers).
- No agent secret handling in v0.3a (checks come later); the config union in the
  stream proto is deliberately forward-compatible so v0.3b adds fields without a
  breaking change.

## Testing

- Unit (table-driven): CSR validation, token state machine (use counting,
  expiry, host binding), facts parsing (fixture `/proc`-style outputs), backoff
  progression, tag upsert precedence (manual wins).
- Integration (testcontainer): token flows end to end, serial registry,
  certificate issuance/renewal/revocation, facts→tags, `monitored` flip.
- Protocol (in-process fakes, spec §18 layer 3): enroll handshake, reconnect
  with backoff, heartbeat cadence, renewal without losing the stream, revoked
  serial rejected mid-stream.
- E2E gate (`internal/e2e/agent_test.go`, Go harness): manager in-process +
  agent loop in-process over loopback TLS; enroll via token (both flows: bind
  to pre-created host, create new host), assert certificate issued, facts
  received, auto tags set, heartbeat visible, revocation ends the stream. The
  Compose + Playwright half of the gate follows the v0.2b pattern once the
  agent container joins the compose test stack.
- Coverage gates as v0.2 (≥ 80 % packages, ≥ 90 % for `internal/ca`,
  `internal/agentapi`, `internal/agent` critical paths), `gofmt` + lint gates,
  race suite split per 2.83.

## Deltas to the architecture spec

- §8 "The agent sends a CSR … to the worker, which forwards it to the manager
  CA" → until v0.6 the agent enrolls and streams against the manager directly
  (no new ports, the worker stays outbound-only to the manager). §8's address
  list/failover wording applies to manager addresses for now.
- §18's agent E2E bullet splits: enrollment/facts is the v0.3a gate; the
  check-pipeline half (default checks, first metrics) is the v0.3b/c gate.
